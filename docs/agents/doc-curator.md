# Doc curator

Weekly unattended job that reconciles `website/content/docs/**.mdx` with what merged to `main`
since its last run. One Claude model authors the edit (`claude-opus-5`); a different one
(`claude-fable-5`) reviews it, with read-only repo tools, before a PR can open. Decision
record: [ADR-0012](../adr/0012-doc-curation-as-a-two-model-pre-gated-job.md). Workflow:
`.github/workflows/doc-curator.yml`. Both prompts point here — this file is the policy.

## Scope

- **In:** existing pages under `website/content/docs/*.mdx`. Update in place.
- **Out:** every other file. In particular `meta.json`, `docs.json`, `AGENTS.md`, `CLAUDE.md`,
  `CONTEXT.md`, anything under `docs/`. Never create a page. Never delete a page.

Read every page each run — the corpus is small and prose-level drift ("100 MB max") does not
match on symbols.

## Inputs

- Merged PRs to `main` since `DOC_CURATOR_LAST_SHA` (titles + bodies: the *why*).
- `git diff <marker>..HEAD` (the *what*). A claim in a doc edit must trace to a hunk or a
  `file:line` in that diff; if it cannot, do not make the edit.

## Author hard limits

1. Net word count of a changed section may not exceed the original by more than **40**.
2. At most **3** sections changed per run. Further drift goes in the PR body under
   "Not attempted", one line each with the page and the reason.
3. Every line outside a changed section is **byte-identical** to the original — no heading
   case, dash, fence-tag, or line-reference changes.
4. No new H2/H3 headings.
5. Do not add a sentence that restates ordering, numbering, or a fact already visible in an
   adjacent code block or table.
6. Follow `docs/agents/writing-guide.md` "Claim discipline" and "Prose" and the MDX
   constraints (no bare `{...}`, links as `./name.mdx`, images `/assets/...`).
7. Do not describe unmerged behaviour in the present tense.

These limits are re-checked mechanically by `scripts/doc-budget.mjs`. A limit failure ends
the run before review; the run summary records which limit and where.

## Reviewer lenses

Return exactly `{ "verdict": "approve" | "reject", "reasons": [string] }`. Reject if any
lens fails; be adversarial — the job is to refute the edit.

1. **Unsupported claim** — a statement not traceable to the supplied diff or PR bodies.
2. **Shorter loses nothing** — a shorter version of any changed sentence conveys the same
   facts.
3. **Scope** — any change outside what the code change requires, or any limit above breached.
4. **Vocabulary** — a term that `CONTEXT.md` lists under `_Avoid_`, or an unqualified
   assurance word per the writing guide.

## Flow

1. Collect inputs. No merges since marker → green no-op, advance nothing.
2. Author proposes; `doc-budget.mjs` checks; reviewer judges against the checkout, citing `file:line`.
3. `reject` → one retry with the reasons appended to the author prompt → `reject` again →
   discard. Never open a rejected PR. The Actions summary is the record.
4. `approve` → `cd website && pnpm install --frozen-lockfile && pnpm build`. Build failure on
   the edit → open an issue (`documentation`, `agent-pr`) with the build log; discard the edit.
5. Open PR: branch `docs/curate-YYYY-MM-DD`, title `docs(site): weekly curation YYYY-MM-DD`,
   labels `agent-pr`, `documentation`. Body: per-section change with citation, reviewer summary,
   "Not attempted" list, and the line
   `Pull request description generated by Claude Code`.
6. If a curator PR is already open, do not open another — comment the new proposal on it.
7. Advance `DOC_CURATOR_LAST_SHA` to the run's `HEAD` only after a PR opens, a comment posts,
   or a clean no-op. A discarded run leaves the marker so the next run retries the window.

## Slot

Curator PRs are exempt from the ADR-0005 one-open-agent-PR slot (they are not on the evidence
path) but a human still merges every one. Step 6 keeps the curator itself serial.
