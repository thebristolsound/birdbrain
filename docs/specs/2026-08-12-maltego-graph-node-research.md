# Maltego graph and node research

**Audience:** Birdbrain product and engineering contributors preparing to brainstorm the in-progress Link Map.

**Research date:** 2026-08-12. This note uses Maltego's first-party product, support, and SDK documentation. Maltego is changing its plan names and has separate Desktop and Browser clients, so boundaries that are inconsistent or time-sensitive are called out rather than reconciled by assumption.

## Executive summary

Maltego's core abstraction is an investigation graph made of typed **Entities** and directed, property-bearing **links**. An Entity has a type, a primary value, additional properties, presentation metadata, and optional notes or attachments. A **Transform** accepts one or more Entities, or in some Desktop-only cases a graph, and returns related Entities and links. **Machines** automate Transform sequences. The Data Hub packages integrations that may install Entity types, Transforms, Transform Sets, Machines, and icons together. [Maltego: Your First Graph](https://docs.maltego.com/en/support/solutions/articles/15000008832-your-first-graph), [Maltego: What is a Transform?](https://docs.maltego.com/en/support/solutions/articles/15000034010-what-is-a-transform-), [Maltego: The Maltego Data Hub](https://docs.maltego.com/en/support/solutions/articles/15000010778-the-maltego-data-hub)

Maltego's mature feature set is broader than a node renderer. It combines a graph data model, automatic duplicate merging, transform discovery and execution, layout and visual-analysis tools, high-node-count simplification, workflow automation, import/export, and collaboration. The useful comparison for Birdbrain is therefore not "which graph library should render the Link Map?" but which parts of that surrounding system belong in a Case-scoped reference view, and which would introduce a new investigation-data or automation subsystem.

The most important caution is evidentiary. Maltego Graph documents graph versions, transform output messages, collaborative author labels, and provider-side request metadata. In the first-party Graph sources reviewed, however, I found no documented equivalent to Birdbrain's immutable captured originals, Content Hash, signed Manifest chain, Trusted Time, or independently checkable Evidence Package. That is an evidence limitation of this research, not proof that no Maltego product or deployment can retain provenance. Maltego Evidence is a separate, optional product in the current portfolio and should not be assumed to describe Maltego Graph behavior. [Maltego: Products and Plans](https://docs.maltego.com/en/support/solutions/articles/15000036759-maltego-products-and-plans), [Maltego: What is logged when I run a Transform?](https://docs.maltego.com/en/support/solutions/articles/15000011924-what-gets-logged-when-i-run-a-transform-)

## Product and terminology boundaries

- **Maltego Graph (Desktop)** is the established installed link-analysis client. All Desktop editions use the same installation; activation selects the plan or license. It supports offline license activation, although full functionality normally depends on Maltego and provider endpoints. [Maltego: Initial activation using a license key](https://docs.maltego.com/en/support/solutions/articles/15000008715-initial-activation-of-maltego-graph-desktop-using-a-license-key), [Maltego: Graph Desktop application requirements](https://docs.maltego.com/en/support/solutions/articles/15000008703-maltego-graph-desktop-application-requirements)
- **Maltego Graph (Browser)** is a distinct browser client. It has graph, map, and table views and can open cloud graphs saved from Desktop, but the clients do not have feature parity. Current SDK documentation says Browser lacks whole-graph Transform inputs, OAuth-authenticated Transforms, global/auth settings, interactive prompts, and Machines; composed Entities are Browser-only, while several overlay and weighting features are Desktop-only or partial in Browser. [Maltego: Navigate the interface](https://docs.maltego.com/en/support/solutions/articles/15000059532-navigate-the-interface), [Maltego: Client Support and Limitations](https://docs.maltego.com/en/support/solutions/articles/15000062391-client-support-and-limitations), [Maltego: Opening Desktop graphs in Browser](https://docs.maltego.com/en/support/solutions/articles/15000060302-opening-graphs-from-graph-desktop-on-graph-browser-)
- The current commercial plans are **Basic**, **Entry**, **Professional**, and **Enterprise**. Basic includes Graph Community Edition; Professional and Enterprise include unrestricted commercial Graph access according to the pricing comparison. Maltego says the older Pro, Organization, Classic, XL, and Enterprise On-premise offerings are legacy and no longer sold, though older documentation and licenses remain in circulation. [Maltego: Products and Plans](https://docs.maltego.com/en/support/solutions/articles/15000036759-maltego-products-and-plans), [Maltego: Pricing](https://www.maltego.com/pricing/), [Maltego: FAQ](https://www.maltego.com/maltego-faq/)
- **Maltego One**, **Search**, **Cases**, **Monitor**, **Evidence**, and **Hunchly** are adjacent products or platform components, not synonyms for Graph. Enterprise bundles can include several of them. Claims about Evidence's social-data preservation or Hunchly's web capture should not be attributed to Graph's node system. [Maltego: Products and Plans](https://docs.maltego.com/en/support/solutions/articles/15000036759-maltego-products-and-plans)

There is current documentation drift. The Community Edition page says a graph can contain up to 10,000 Entities, while the broader products page says Basic has no limit on how many Entities can be pasted onto a graph. These claims can coexist if the latter describes only paste operations, but the sources do not explicitly resolve the boundary. The pricing page also marks some Browser availability as "available soon" while Browser documentation and release notes describe an active client. Any licensing or capacity decision would need confirmation from Maltego rather than extrapolation from these pages. [Maltego: What is Graph Community Edition?](https://support.maltego.com/en/support/solutions/articles/15000018947-what-is-maltego-graph-community-edition-ce-), [Maltego: Products and Plans](https://docs.maltego.com/en/support/solutions/articles/15000036759-maltego-products-and-plans), [Maltego: Pricing](https://www.maltego.com/pricing/)

## Entity and node model

### Types, identity, and merging

Maltego calls graph nodes **Entities**. An Entity's type states what kind of information it represents; its value is the primary field; and properties hold additional fields. Entity categories organize types in the palette but are not themselves graph relationships. [Maltego: Your First Graph](https://docs.maltego.com/en/support/solutions/articles/15000008832-your-first-graph), [Maltego: Create New Entity](https://docs.maltego.com/en/support/solutions/articles/15000010462-create-new-entity)

When a new Entity reaches a graph, Maltego automatically merges it with an existing Entity when type and main value match and all properties marked for strict matching also match. Loose properties do not participate in that identity test. This makes merge behavior part of the Entity schema and Transform contract rather than merely a renderer option. Notes are concatenated on merge, while the incoming bookmark replaces the prior bookmark according to the advanced-creation documentation. [Maltego: Advanced Entity Creation](https://docs.maltego.com/en/support/solutions/articles/15000019246-advanced-entity-creation)

### Properties and presentation

Custom Entity definitions distinguish:

- the **main property**, also called Entity value;
- other statically defined properties;
- **dynamic properties** added by the Transform that returned a particular Entity;
- display information, which is presentation-only and is not sent back to a Transform;
- an editable value and a separately configurable display value; and
- a type icon, optional large image derived from a URL property, and SDK-defined overlays or weight in supported clients.

The custom-Entity wizard documents string, date, integer, and double property types. It also permits a display value different from the edited/main value, such as showing a page title while retaining its URL as the operational value. Entity properties and the Entity value are passed to Transforms; Detail View information is not. [Maltego: Create New Entity](https://docs.maltego.com/en/support/solutions/articles/15000010462-create-new-entity), [Maltego: Property View Window](https://docs.maltego.com/en/support/solutions/articles/15000019237-property-view-window), [Maltego: Custom Entity Guidelines](https://docs.maltego.com/en/support/solutions/articles/15000019245-custom-entity-guidelines)

### Inheritance and custom types

A custom Entity can inherit from a base Entity. It receives the base properties and can run Transforms registered for the base type; a Transform registered only for the child does not become available on the parent. Maltego recommends inheritance and stable namespacing to avoid duplicated Entity types, properties, and Transforms across integrations. [Maltego: Create New Entity](https://docs.maltego.com/en/support/solutions/articles/15000010462-create-new-entity), [Maltego: Custom Entity Guidelines](https://docs.maltego.com/en/support/solutions/articles/15000019245-custom-entity-guidelines)

An Entity can be palette-visible or Transform-return-only. It can carry an icon, note, bookmark color, and file or URL attachment. Desktop graphs show an attachment marker, and collection logic excludes Entities with notes or attachments from collection nodes. [Maltego: Create New Entity](https://docs.maltego.com/en/support/solutions/articles/15000010462-create-new-entity), [Maltego: Your First Graph](https://docs.maltego.com/en/support/solutions/articles/15000008832-your-first-graph), [Maltego: Collections Tab](https://docs.maltego.com/en/support/solutions/articles/15000010775-collections-tab)

Current SDK documentation also describes **composed Entities**, where a property can itself contain an Entity. That feature is documented as Browser-only as of 2026-04-27, which is a useful example of why "the Maltego Entity model" cannot be treated as one stable cross-client schema. [Maltego: Writing Your First Transform](https://docs.maltego.com/en/support/solutions/articles/15000062362-writing-your-first-transform-quickstart-), [Maltego: Client Support and Limitations](https://docs.maltego.com/en/support/solutions/articles/15000062391-client-support-and-limitations)

## Links and relationships

Links are first-class graph objects rather than merely inferred connector lines. The current SDK models source and target IDs, direction reversal, line style, color, thickness, label, a graph-unique link ID, and arbitrary custom properties. A Transform returning an ordinary Entity or list causes the client to create links from inputs to outputs; returning a `MaltegoGraph` allows the developer to add a custom network of Entities and links. Graph input is documented as Desktop-only. [Maltego: SDK API Reference](https://docs.maltego.com/en/support/solutions/articles/15000062354-sdk-api-reference), [Maltego: Writing Your First Transform](https://docs.maltego.com/en/support/solutions/articles/15000062362-writing-your-first-transform-quickstart-)

Direction is semantically meaningful. Transform integrations can reverse the default input-to-output link, and older TRX documentation also describes a bidirectional direction value. Maltego's integration guidance recommends choosing direction to reflect ownership, hosting, or hierarchy so hierarchical layouts remain meaningful. Labels can describe the relationship, while style, thickness, and color add visual encoding. [Maltego: Building Integrations for Maltego](https://docs.maltego.com/en/support/solutions/articles/15000053545-building-integrations-for-maltego), [Maltego: Python TRX Library Reference](https://docs.maltego.com/en/support/solutions/articles/15000024275-python-trx-library-reference-itds-)

Operators can also draw manual links and edit their properties. Transform-created link properties are read-only in the Desktop UI, whereas manually created link properties are editable. Global settings can hide Transform or custom link labels, and individual link visibility can override the global setting. [Maltego: Creating Manual Links](https://docs.maltego.com/en/support/solutions/articles/15000010433-creating-manual-links), [Maltego: View Tab](https://docs.maltego.com/en/support/solutions/articles/15000010458-view-tab)

This separation leaves one provenance ambiguity: a Transform-created link can expose a Transform label and read-only properties, but the reviewed Graph documentation does not specify an immutable, queryable record tying every returned Entity and link to provider, request parameters, execution time, source response, and software version.

## Transforms, integrations, and developer surface

A **Transform** is code that accepts graph information, queries or computes related information, and returns Entities. Maltego encourages small, reusable outputs so later Transforms can pivot through them. A Transform can accept a single typed Entity, a typed list, or, on Desktop, a selected graph including links. Outputs may be none, one Entity, a list, a custom graph, or an asynchronous stream of Entities in the current Python SDK. [Maltego: What is a Transform?](https://docs.maltego.com/en/support/solutions/articles/15000034010-what-is-a-transform-), [Maltego: Writing Your First Transform](https://docs.maltego.com/en/support/solutions/articles/15000062362-writing-your-first-transform-quickstart-)

The execution and distribution layers are separate:

- A **Transform Server** runs remote Transform code.
- A **Transform Distribution Server** or TDS distributes discovery/configuration and brokers requests in the older documented architecture.
- A **Local Transform** runs a configured command-line program on the same machine as Graph Desktop and emits its response through standard output. It can be written in any language and can access machine-local or VPN-only resources.
- A **Transform Set** groups related discovery entries for convenient execution; it is not an automated workflow.
- A **Data Hub item** is an installable integration bundle. It can install Transforms, Transform Sets, Entities, Machines, and icons, and can request provider credentials or settings.

[Maltego: Guide to Building Maltego Integrations](https://docs.maltego.com/en/support/solutions/articles/15000034012-about-this-guide), [Maltego: Local Transforms](https://docs.maltego.com/en/support/solutions/articles/15000034021-local-transforms), [Maltego: Transform Sets](https://docs.maltego.com/en/support/solutions/articles/15000062359-transform-sets), [Maltego: The Maltego Data Hub](https://docs.maltego.com/en/support/solutions/articles/15000010778-the-maltego-data-hub)

Local Transforms avoid server infrastructure and can keep data off Maltego infrastructure, but must be installed and updated on every workstation. Maltego's documentation also says the local form lacks some settings and slider capabilities and may leave credentials on the machine. The current SDK compatibility table adds broader cross-client constraints: whole-graph input, OAuth, interactive prompts, global/auth settings, and Machines are Desktop-only, while multiple-Entity Browser execution may run once per selected Entity rather than as a batch. [Maltego: Local Transforms](https://docs.maltego.com/en/support/solutions/articles/15000034021-local-transforms), [Maltego: Client Support and Limitations](https://docs.maltego.com/en/support/solutions/articles/15000062391-client-support-and-limitations)

The first-party developer surface reviewed is integration-oriented: the current `maltego-transforms` Python SDK registers custom Entity classes, Transforms, Transform Sets, Machines, settings, and discovery metadata; the older `maltego-trx` library speaks the XML Transform protocol and can target local or server deployments. This is not evidence of a supported general-purpose API for controlling every Graph UI or persistence operation. [Maltego: SDK API Reference](https://docs.maltego.com/en/support/solutions/articles/15000062354-sdk-api-reference), [Maltego: Writing Your First Transform](https://docs.maltego.com/en/support/solutions/articles/15000062362-writing-your-first-transform-quickstart-), [Maltego: Local Transforms Example](https://docs.maltego.com/en/support/solutions/articles/15000017605-local-transforms-example)

## Graph interaction and analysis

### Layout and views

Desktop documents block, hierarchical, circular, organic, and interactive-organic layouts. Interactive organic relays out only the neighborhood affected by newly returned Entities, reducing work and preserving more of the existing arrangement. Desktop can lock or freeze layout while results arrive. Browser documents hierarchical, organic, circular, and orthogonal layouts. [Maltego: Graph Sidebar](https://docs.maltego.com/en/support/solutions/articles/15000009615-maltego-graph-sidebar), [Maltego: Visualizing Results with Layouts](https://docs.maltego.com/en/support/solutions/articles/15000059535-visualizing-results-with-layouts)

Maltego separates **layout** from **view**. Layout controls position; Desktop Viewlets control size and color based on graph properties such as total, incoming, or outgoing degree, Entity rank, Entity weight, or Entity type. A list view exposes Entities or links in a table and displays temporal properties when present. Custom Views are supported and can be included in exported client configuration. [Maltego: Graph Sidebar](https://docs.maltego.com/en/support/solutions/articles/15000009615-maltego-graph-sidebar), [Maltego: View Tab](https://docs.maltego.com/en/support/solutions/articles/15000010458-view-tab), [Maltego: Export Config](https://docs.maltego.com/en/support/solutions/articles/15000010802-export-config)

### Find, filter, selection, and focus

Desktop Quick Find can search Entity type, properties, notes, Detail View, and link text, highlight matches, list them, and optionally zoom to them. It can also search saved local graph files. Browser provides property filters for text, numeric, and time values, supports regular expressions and AND/OR combinations, and highlights matching Entities. Browser's graph interaction modes distinguish pan, selection, and manual-link actions and permit multi-Entity/link selection. [Maltego: Find in Graph](https://docs.maltego.com/en/support/solutions/articles/15000010431-find-in-graph), [Maltego: Filters and Quick Find](https://docs.maltego.com/en/support/solutions/articles/15000059549-finding-relevant-entities-with-filters-and-quick-find), [Maltego: Navigate the Interface](https://docs.maltego.com/en/support/solutions/articles/15000059532-navigate-the-interface)

Desktop selection tools can add or isolate parents, children, similar siblings, neighbors, leaves,
bookmarked Entities, types, and the connecting paths between selected Entities. Link-selection
tools separately select incoming, outgoing, or both link directions and can reverse manually
created links. These commands analyze or change the selection over the existing graph; they do not
run Transforms. [Maltego: Entity Selection](https://docs.maltego.com/en/support/solutions/articles/15000010432-entity-selection),
[Maltego: Link Selection](https://docs.maltego.com/en/support/solutions/articles/15000010454-link-selection)

Browser histograms expose the distribution of numeric or temporal Entity properties and let the
investigator narrow the highlighted range with draggable bounds. This is a property-analysis view,
not another graph layout. [Maltego: Visualizing Trends Using Histograms](https://docs.maltego.com/en/support/solutions/articles/15000060300-visualizing-trends-using-histograms)

Five-color bookmarks categorize Entities and can drive selection and bulk action. Notes attach free text directly to Entities. Attachments attach a local file or fetched URL to an Entity. These are graph-object affordances; they are not documented as assertions with separate authorship, evidence state, or confidence fields. [Maltego: Categorizing Key Findings with Bookmarks](https://docs.maltego.com/en/support/solutions/articles/15000059547-categorizing-key-findings-with-bookmarks), [Maltego: Adding Notes to Entities](https://docs.maltego.com/en/support/solutions/articles/15000060295-adding-notes-to-entities), [Maltego: Your First Graph](https://docs.maltego.com/en/support/solutions/articles/15000008832-your-first-graph)

### Collections and scale management

Desktop **collection nodes** are visual simplifications over the underlying graph, not replacement data. They group similar Entities of one type after a configurable threshold, preserve selection state, allow inspection and Transform execution on contained Entities, and let an Operator pin an Entity out of the collection. An example reduces a 4,164-Entity, 4,489-link graph to a more legible view. Hidden members still exist and retain ordinary graph functionality. [Maltego: Collections Tab](https://docs.maltego.com/en/support/solutions/articles/15000010775-collections-tab)

That distinction is valuable: simplification, type filtering, and deletion are different operations. Maltego's collection UI signals full versus partial selection and allows filtered list inspection, reducing the risk that a collapsed visual group is mistaken for one underlying Entity.

## Machines and automation

A **Machine** is a reusable macro written in Maltego's Machine scripting language. It automates Transform execution and can run Transforms sequentially, in parallel, or both. Machines can include filters and human selection steps; current SDK documentation describes them as versionable workflow assets and says custom-server Machines are Desktop-only. [Maltego: Introduction to Maltego Machines](https://docs.maltego.com/en/support/solutions/articles/15000047415-introduction-to-maltego-machines), [Maltego: Machines SDK](https://docs.maltego.com/en/support/solutions/articles/15000062348-machines-sdk-)

The documented DSL can filter by type, value, age, properties, bookmark, total degree, and incoming or outgoing degree. It can run Transforms, delete nodes or branches, bookmark results, prompt the Operator to select results, change layout, save a graph, export an image, and run perpetually. A command-line invocation can start a named Machine from a typed starting Entity. Some Machines are bundled, some arrive through third-party Data Hub items, and some are custom. Hub-installed Machines are read-only unless cloned. [Maltego: Machine Syntax Reference](https://docs.maltego.com/en/support/solutions/articles/15000019254-machine-syntax-reference), [Maltego: Managing Machines](https://docs.maltego.com/en/support/solutions/articles/15000010790-managing-machines)

This makes Machines materially different from Birdbrain's current Link Map baseline: they mutate and expand the investigation graph by executing data-gathering logic. Treating layout or neighborhood navigation as a Machine analogue would understate the scope.

## Collaboration, sharing, and portability

Desktop's legacy shared-graph sessions allow multiple people to read and write the same graph over an XMPP communication server. The graph is stored locally by participants rather than on the communications server, and the session exists only while at least one participant remains connected. Every participant has full graph read/write control; added Entities display the contributor's alias. Layout changes are shared, while view changes are local. The public or private communications server transports end-to-end encrypted graph traffic according to the documentation. [Maltego: Collaboration](https://docs.maltego.com/en/support/solutions/articles/15000010791-collaboration), [Maltego: Sharing a Graph](https://docs.maltego.com/en/support/solutions/articles/15000010792-sharing-a-graph)

Cloud graphs saved in Maltego Cases use version history. Browser is documented as making a daily backup, while Desktop-to-Cases creates a version on each explicit save; earlier versions can be viewed or restored. These are recovery/versioning features, not a documented append-only audit history. [Maltego: Restoring Your Graph Using Version History](https://docs.maltego.com/en/support/solutions/articles/15000059550-restoring-your-graph-using-version-history), [Maltego: Managing Graph Versions in Cases](https://docs.maltego.com/en/support/solutions/articles/15000061571-managing-graph-versions-in-cases)

Graph Community Edition documentation lists image, PDF, CSV/XLS/XLSX, GraphML, and Entity-list export, plus tabular import and copy/paste. Browser can export a PDF or `.mtgx` file for Desktop. Custom Entity definitions and broader client configuration can be shared in `.mtz` files; configuration exports exclude stored API keys and require Local Transform scripts to be copied separately. [Maltego: What is Graph Community Edition?](https://support.maltego.com/en/support/solutions/articles/15000018947-what-is-maltego-graph-community-edition-ce-), [Maltego: Navigate the Interface](https://docs.maltego.com/en/support/solutions/articles/15000059532-navigate-the-interface), [Maltego: Import and Exporting Entities](https://docs.maltego.com/en/support/solutions/articles/15000010770-import-and-exporting-entities), [Maltego: Export Config](https://docs.maltego.com/en/support/solutions/articles/15000010802-export-config)

## Provenance, evidence, and reproducibility

The reviewed Graph sources document several useful traces:

- Transform-created links are distinguishable from manual links in Desktop and their properties are read-only. [Maltego: Creating Manual Links](https://docs.maltego.com/en/support/solutions/articles/15000010433-creating-manual-links)
- Transform Output records Transform names, result counts, warnings, errors, and Entity links during use, and the text can be saved manually. [Maltego: Transform Output](https://docs.maltego.com/en/support/solutions/articles/15000019239-transform-output)
- Shared sessions label an Entity with the alias of the person who added it. [Maltego: Collaboration](https://docs.maltego.com/en/support/solutions/articles/15000010791-collaboration)
- Maltego says its Transform infrastructure logs request time, source IP, Transform URL/name, derived Desktop API key, user agent, and HTTP size metadata, but not the HTTP body, investigation query, or returned results. Third-party Transform providers may have their own behavior. [Maltego: What is logged when I run a Transform?](https://docs.maltego.com/en/support/solutions/articles/15000011924-what-gets-logged-when-i-run-a-transform-)
- Saved cloud graphs have restorable versions, with different version-creation schedules documented for Browser and Desktop. [Maltego: Restoring Your Graph Using Version History](https://docs.maltego.com/en/support/solutions/articles/15000059550-restoring-your-graph-using-version-history), [Maltego: Managing Graph Versions in Cases](https://docs.maltego.com/en/support/solutions/articles/15000061571-managing-graph-versions-in-cases)

Those mechanisms can help explain graph state, but the reviewed sources do not establish that they provide a complete reproducible lineage for each Entity or link. In particular, no reviewed Graph page specified retention of the provider response, immutable acquisition input/output, hash binding between source material and derived graph objects, an append-only signed mutation history, trusted third-party time, or independent verification. This should be treated as **not documented in the reviewed scope**, not as a categorical claim about every Maltego deployment.

For Birdbrain, this distinction is structural. A Capture and its Content Hash, Manifest position, Trusted Time, and Integrity Status describe acquisition and integrity. A graph node or edge describing investigation subject matter is an assertion or navigation aid. Visual proximity, merge identity, Transform output, or a collaborator label must not silently become evidence provenance.

## Scale and commercial constraints

- The current Community Edition page says up to 10,000 Entities per graph and at most 24 results per Transform. The current Basic-plan page separately says there is no limit on the number of pasted Entities, so the exact graph ceiling needs direct confirmation. [Maltego: What is Graph Community Edition?](https://support.maltego.com/en/support/solutions/articles/15000018947-what-is-maltego-graph-community-edition-ce-), [Maltego: Products and Plans](https://docs.maltego.com/en/support/solutions/articles/15000036759-maltego-products-and-plans)
- Basic includes 200 Maltego Data credits per month and limited provider access. Professional and Enterprise change data access and credit allowances; third-party Connectors may require separate credentials or paid accounts. Graph capability and data entitlement are therefore different constraints. [Maltego: Pricing](https://www.maltego.com/pricing/), [Maltego: The Maltego Data Hub](https://docs.maltego.com/en/support/solutions/articles/15000010778-the-maltego-data-hub)
- Maltego recommends 16 GB RAM and an Intel i7 for Desktop and states that adding results and recomputing layout on large graphs consumes substantial CPU and memory. Interactive-organic layout and collection nodes are explicit scale-management mechanisms. [Maltego: Graph Desktop application requirements](https://docs.maltego.com/en/support/solutions/articles/15000008703-maltego-graph-desktop-application-requirements), [Maltego: Graph Sidebar](https://docs.maltego.com/en/support/solutions/articles/15000009615-maltego-graph-sidebar), [Maltego: Collections Tab](https://docs.maltego.com/en/support/solutions/articles/15000010775-collections-tab)
- Browser/Desktop capability differences constrain integration portability independently of plan. A cross-client Transform must avoid several Desktop-only capabilities and test both clients. [Maltego: Client Support and Limitations](https://docs.maltego.com/en/support/solutions/articles/15000062391-client-support-and-limitations)

Maltego's published capacities should not become Birdbrain requirements. Maltego is designed for graph expansion and analysis; Birdbrain's ratified Link Map baseline is a deterministic, Case-scoped projection with a 20-node display ceiling. The relevant lesson is that visual scale rules need explicit semantics, not that Birdbrain should target Maltego-sized graphs.

## Birdbrain Link Map comparison

Birdbrain's [ratified implementation program](https://github.com/thebristolsound/birdbrain/issues/382) defines an in-progress Link Map over the Stage 2 references index derived from typed Note mentions. Its nodes are Note, Capture, Selector, and Tag; dashed edges represent authored references and solid accent edges represent Note-to-Note backlinks. It renders deterministically on a 3-by-8 lattice. Hover previews and click focus fade the non-neighborhood; type chips ghost rather than delete hidden types; a node click focuses and a double-click opens it. The map has a 20-node ceiling with visible `showing N of M` disclosure, retains all Notes, then fills remaining slots by highest degree. The feasibility assessment additionally requires stable target type/ID, preserved broken targets, main-process reference derivation, and no unbounded full-graph render. These are decided baseline constraints, not a shipped feature.

One baseline edge case remains unresolved in the cited program: a hard 20-node ceiling and retaining
all Notes cannot both hold when a Case has more than 20 Notes. This note treats that as a question
for the upcoming design work rather than assuming which constraint wins.

## Questions to carry into brainstorming

1. What is the Link Map's promised answer: "what does this Note reference," "how is this Case organized," or "what investigation subjects are related"? Those are different graphs.
2. Are all edges derived from existing durable records, or could an Operator author a relationship directly? If both exist, how are origin and editability represented?
3. Should a Mention's reverse Backlink be drawn as a second edge, or is it a query/view over one directed reference? Maltego's direction model shows the analytical value of direction, but not the right answer for Birdbrain's derived Backlink semantics.
4. When a Case has more than 20 Notes, which wins: the 20-node ceiling or the requirement to retain all Notes? Beyond that edge case, how should the UI distinguish filtering, focus, ghosting, and truncation so they cannot be mistaken for one another?
5. What happens when a mentioned target is deleted, imported without its target, renamed, or belongs to an older Case Archive schema? The feasibility assessment already requires broken targets to remain representable.
6. Can a graph-derived operation affect an Evidence-Affecting Path? If it invokes Recapture, extraction, Capture Analysis, export, or deletion, it crosses a boundary that a view-only Link Map does not.
7. Which fields would a machine-readable graph export contain, and how would a verifier distinguish authored Note content, derived references, investigation subject matter, and Capture integrity metadata?
8. What accessibility representation accompanies the canvas: keyboard traversal, a synchronized list/table, edge descriptions, focus order, zoom-independent labels, and announcements for hidden or truncated content?
9. How should a Case with many references degrade? Maltego uses incremental layout, collection nodes, filters, and list views; Birdbrain needs an explicit answer compatible with deterministic rendering and the current Overview context.
10. Does Birdbrain need extensible node types at all? Maltego's inheritance and Transform ecosystem solve integration problems; adopting that abstraction would be a product-domain expansion, not a prerequisite for showing Birdbrain's existing typed references.

## Evidence limits

- Maltego's documentation set mixes recently revised 2026 SDK and plan pages with older Desktop articles, legacy TRX material, and product names that remain searchable after retirement. This note prefers the newer source when they conflict and records unresolved inconsistencies.
- Browser and Desktop behavior differ. A capability documented for one is not assumed to exist in the other.
- Product/plan access, provider entitlements, credits, and numeric limits can change. Values here are a 2026-08-12 snapshot and should be rechecked before procurement or implementation decisions.
- First-party pages describe features but do not expose every persistence schema, graph file specification, server-side retention rule, or security property. Absence from the reviewed sources is reported as "not documented," not "does not exist."
- No software was installed and no live Maltego account was exercised. Interaction details are based on Maltego's official documentation rather than an independent runtime test.
- This note compares Maltego with the in-progress Link Map handoff and feasibility assessment. It does not select a graph library, propose a Birdbrain schema, or approve a design.
