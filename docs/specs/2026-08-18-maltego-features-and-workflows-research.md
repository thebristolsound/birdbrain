Date: 2026-08-18 (every page cited below was fetched on this date unless noted).
Audience: Birdbrain contributors evaluating link-analysis / investigation features (Link Map and beyond).
Scope: **detailed** feature-set inventory of Maltego Graph (Desktop and Browser) and the adjacent
Maltego products, plus concrete step-by-step workflows as Maltego's own documentation and blog

Relation to prior work: the 2026-08-12 note ("Maltego graph and node research") already covers the
Entity/link data model, merging rules, the Transform concept, plan/product boundaries, Desktop-vs-
Browser parity, and the Birdbrain Link Map comparison. This note does not repeat that material; where

Method: first-party sources only; `docs.maltego.com` / `support.maltego.com` (same Freshdesk
knowledge base, two hostnames), `maltego.com` product/blog/Transform-Hub pages, the `MaltegoTech`

## Executive summary

- Maltego Graph (Desktop) is a ribbon-driven Java client whose whole surface is organized around
  ribbon tabs (Investigate, View, Entities, Collections, Transforms, Machines, Collaboration,
  Import|Export, Windows) plus a left graph sidebar (layouts, freeze, views) and dockable windows
  (Detail View, Property View, Entity Palette, Transform Output, Machines, Overview, Chat/Collaboration,
  Run View, Hub Transform Inputs). Almost every feature in the inventory below lives in one of those.
- Graph (Browser) is a separate, thinner client inside Maltego One (`app.maltego.com`): graph / map /
  table views, filters + histograms, bookmarks, viewlets (link-count sizing only), PDF and `.mtgx`
  export, an AI Assistant, E2E-encrypted cloud graphs in Maltego Cases, and (new since the 08-12
  note) a "Local and Cloud Storage" model where graphs and searches can be saved to a linked local
  folder as `.mtgj` files. File import (`.csv`/`.xlsx`) is **still not supported** in Browser.
- Data access is the Data Hub: "Data Pass" modules (Maltego-hosted, credit-metered, 120+ providers,
  12,000+ "search methods") plus 100+ bring-your-own-key "Connectors"; each Hub item can install
  Transforms, Transform Sets, Entities, Machines and icons. Machines (Maltego scripting language) are
  the automation layer and remain **Desktop-only** for custom servers, though Browser release notes now
  reference a "Machine Operator"; see drift list.
- Documented investigator workflows cluster into: infrastructure/attack-surface footprinting (L1/L2/L3
  Machines and the DNS→IP→Netblock→AS→Company data model), person-of-interest pivoting
  (email/phone/alias → identity providers → social/breach data), IOC/malware enrichment (hash → VT /
  MISP / Shodan / Splunk), corporate structure (OpenCorporates/Orbis officer↔company loops),
  cryptocurrency "Address → Transaction → Address" tracing, tabular import of own data, custom
  Transform servers via the `maltego-transforms` SDK or legacy TRX/iTDS, and hand-off via Cases /
  shared graphs / PDF reports.
- Adjacent products are separate systems, not Graph features: **Search** (person-identifier OSINT
  search that exports to Graph), **Monitor** (ex-PublicSonar real-time social monitoring with cases,
  filters, dashboards, alerts), **Evidence** (ex-SNH social-network crawler with crawling profiles,
  runners, full-page screenshots), **Hunchly** (browser capture; a local-Transform pack pulls Hunchly
  cases into Graph), **Cases/Admin** (storage, sharing roles, credits).

### 1.2 Layouts, views/viewlets, list view (Desktop sidebar & View tab)

- **Graph controls**: Full Screen (Alt+Enter), **Lock Layout** (existing nodes stay put; new results still laid out), **Full vs Incremental Layout** (recommended in collaborative sessions), **Freeze** (stop re-layout while many Transforms return; faster processing) and **Refresh** (manual relayout when frozen). [Maltego Graph Sidebar](https://docs.maltego.com/en/support/solutions/articles/15000009615-maltego-graph-sidebar)
- **Layouts**: Block (lowest hierarchy level in a block, sorted by type then weight), Hierarchical (tree/file-manager), Circular (most-linked at center), Organic (tight packing by connectivity), **Interactive Organic** (only the neighbourhood of new results moves; less tightly packed; better performance on large graphs). Browser documents Hierarchical, Organic, Circular and Orthogonal (see 08-12 note). [Graph Sidebar](https://docs.maltego.com/en/support/solutions/articles/15000009615-maltego-graph-sidebar)
- **Views (Viewlets)**, seven built-in: Normal (icons close-up; equal-size type-colored balls in "Legend View" when zoomed out), **List View** (tabular; Entity or Link mode; automatic **Time Column** when any Entity has a temporal property: date/datetime/daterange/date array; format `yyyy-MM-dd HH:mm:ss.S Z`; earliest date wins, epoch ignored, hidden when none), **Diverse Descent** (size by incoming links, weighted higher when grandparents differ), Ball size by All Links / Incoming / Outgoing / **Entity Rank** (own links + neighbours' links) / **Entity Weight**. Custom viewlets can be authored (Manage View window); the Tatum crypto blog shows a working viewlet script that scales `maltego.BTCTransaction` nodes by a `total_input` property. [Graph Sidebar](https://docs.maltego.com/en/support/solutions/articles/15000009615-maltego-graph-sidebar), [View Tab](https://docs.maltego.com/en/support/solutions/articles/15000010458-view-tab), [Introducing Tatum to Maltego](https://www.maltego.com/blog/introducing-tatum-to-maltego/)
- **View tab extras**: Entity Alignment; Link Labels & Properties: *Show Custom Link Labels* (global, overridable per link), *Show Transform Link Labels* (show the Transform that created the link), *Properties Affect Appearance*; global *Entity Notes* visibility. [View Tab](https://docs.maltego.com/en/support/solutions/articles/15000010458-view-tab)
- **Browser viewlets** are a strict subset: Number of Incoming / Outgoing / All Links, with a "best for" table (incoming = targets, outgoing = propagators/bots, all = hubs). [Visualizing Results with Viewlets](https://docs.maltego.com/en/support/solutions/articles/15000059552-visualizing-results-with-viewlets)

### 1.3 Windows tab: Detail View, Property View, Palette, Transform Output, Hub Transform Inputs

- **Detail View**: Transform-author-supplied detail (not editable once returned); multi-select turns it into a sortable, searchable table (columns: type icon, value, bookmark color, **pinned** flag, collection size, incoming links, outgoing links, weight); "Sync Selection to Graph"; right-click to run Transforms from the table. [Detail View](https://docs.maltego.com/en/support/solutions/articles/15000019236-detail-view)
- **Entity Palette**: categories, recently used at top, Ctrl+F search; grows as Hub items install Entities. [Entity Palette](https://docs.maltego.com/en/support/solutions/articles/15000019238-entity-palette)
- **Transform Output**: per-run messages (Transform name, result count, warnings, errors); message-type filter; each message links to the causing Entity; Find / text Filter / Wrap / font / **Save As** text file. [Transform Output](https://docs.maltego.com/en/support/solutions/articles/15000019239-transform-output)
- **Hub Transform Inputs**: settings shared across a Hub item's Transforms, set once. [Hub Transform Inputs](https://docs.maltego.com/en/support/solutions/articles/15000019244-hub-transform-inputs)
- **Base64 Entity properties** (since 4.6.0): dropping a file on the graph auto-populates a Base64 property; single-file attach to an existing Entity; multi-file drag & drop; Transforms may return Base64 images that render on the graph; **limits: 1 MB to render / attach (else property set to empty string), 10 MB max payload to a Transform Server**. [Base64 Entity Properties](https://docs.maltego.com/en/support/solutions/articles/15000056418-base64-entity-properties)

### 1.4 Entities management (Desktop Entities tab)

- Manage Entities (Entity Manager: list, edit, delete), Create New Entity wizard, Icon Manager (browse/search built-ins, add PNG icons into a category), Import/Export Entities as `.mtz` with optional **AES-128 password encryption**; custom Entities also travel inside a saved graph opened in a clean client. Standard Entities ship via Hub items; a non-standard type used by a TDS Transform must be in the TDS **Paired Configuration**. [Managing Entities](https://docs.maltego.com/en/support/solutions/articles/15000010769-managing-entities), [Icon Manager](https://docs.maltego.com/en/support/solutions/articles/15000010771-icon-manager), [Import and Exporting Entities](https://docs.maltego.com/en/support/solutions/articles/15000010770-import-and-exporting-entities), [Standard Entities](https://docs.maltego.com/en/support/solutions/articles/15000034102-standard-entities)
- Entity schema details (main property, dynamic properties, display value, inheritance, strict-match merging) are in the 08-12 note.
- **Composed Entities (Browser-only)**: a parent "Composed Profile" embedding Name/Alias/Email/Phone etc.; produced by the *Deep Dive - Facebook / Instagram / LinkedIn / Telegram / TikTok / Weibo / X-Twitter / YouTube* Transform Sets; Expand/Collapse on canvas; running a Transform on the parent runs it on all embedded Entities; badge shows embedded count; vendor-specific types (for example `maltego.vetric.FacebookPost`) are Transform-output-only, not in the palette. Desktop 4.11.0 can open cloud graphs containing composite Entities **read-only**. [Composition and Composed Entities](https://docs.maltego.com/en/support/solutions/articles/15000061976-composition-and-composed-entities), [Desktop release notes 4.11.0](https://docs.maltego.com/en/support/solutions/articles/15000053036-release-notes-for-maltego-graph-desktop-)

### 1.5 Transforms tab: Transform Manager, Data Hub, Local Transforms, Managed Services

- **Transform Manager** (three tabs): *All Transforms* (columns Transform / Status / Location (TAS) / Default Set / Input / Output; search by name; per-Transform info incl. author, disclaimers; per-Transform settings such as API keys, timeouts, "popup" fields), *Transform Servers* (enable/disable servers), *Transform Sets* (create/edit by drag-drop; for example the built-in "Resolve to IP" set groups DNSName/MX/NS/Website→IP). Docs recommend it as the way to see every Transform an integration offers irrespective of the selected Entity. [The Transform Manager](https://docs.maltego.com/en/support/solutions/articles/15000010779-the-transform-manager)
- **Data Hub**: lists Data Providers; Install → credentials prompt → wizard → summary. A Hub item may install **Transforms, Transform Sets, Entities, Machines, Icons**. Per-item Settings ("Transform Seed Settings") hold global settings/API keys. *Refresh* (re-reads hub metadata) vs *Update* (updates installed Transforms; client also auto-updates periodically). Manual `+` adds an arbitrary Transform Seed URL under "Internal Hub Items." A fresh install has **no** Entities/Transforms until Hub items are installed. [The Maltego Data Hub](https://docs.maltego.com/en/support/solutions/articles/15000010778-the-maltego-data-hub), [Why are there no Transforms in my context menu…](https://docs.maltego.com/en/support/solutions/articles/15000011971-why-are-there-no-transforms-in-my-context-menu-and-no-entities-in-my-palette-), [Initial Data Source Installation](https://docs.maltego.com/en/support/solutions/articles/15000008825-initial-data-source-installation-for-maltego-graph)
- **Data Pass vs Connectors**: Data Pass = Maltego-hosted modules grouped Person of Interest / Cyber Threat Intelligence / Cryptocurrency / Darkweb / Corporate Intelligence / **Utilities** (reverse image search, translation, web search; "many of the former Maltego Standard Transforms"); metered in Maltego credits per Transform run; "over 120 Data Providers with over 12,000 search methods." Connectors = 100+ pre-built integrations where you bring the provider's API key. Provider list and per-Transform credit costs are behind a Maltego-ID login (not fetched). [Data Pass and Connectors for Maltego Graph](https://docs.maltego.com/en/support/solutions/articles/15000058711-data-pass-and-connectors-for-maltego-graph), [How to install Data Pass and Connectors](https://docs.maltego.com/en/support/solutions/articles/15000061559-how-to-install-data-pass-and-connectors-)
- **Local Transforms** (Desktop): New Local Transform wizard → meta (display name, description, ID, author), input Entity type, optional set; then Command (interpreter/exe), Script/Parameters, Working Directory; appears as a "Local Transforms" Hub item in the context menu. Pros/cons per Maltego: machine-specific, nothing traverses Maltego infra, any language, no server; but per-machine install/update, **no slider or settings**, credentials sit on the analyst's machine. TRX caveat: local Transforms receive dummy `type`, `weight`, `slider`, `transformSettings`. `maltego-trx` ≥1.6.0 auto-generates an `.mtz` for local Transforms. [Local Transforms (Desktop)](https://docs.maltego.com/en/support/solutions/articles/15000010781-local-transforms), [Local Transforms (Dev)](https://docs.maltego.com/en/support/solutions/articles/15000034021-local-transforms), [`maltego-trx` README](https://github.com/MaltegoTech/maltego-trx)
- **Managed Services** (OAuth sign-in per user so provider rate limits apply per user; callback protocol/port configurable; Maltego never stores account credentials, only a temporary token). [Managed Services](https://docs.maltego.com/en/support/solutions/articles/15000010784-managed-services)
- **Web-search source discovery**: search-engine Transforms store source URLs in Entity properties; the "To URLs [show Search Engine results]" family (now *Expand Search Engine Results [Search Engine]*) plots them with page title as display value. [Web Search Transforms: Discover Entity Source](https://docs.maltego.com/en/support/solutions/articles/15000020255-web-search-transforms-discover-entity-source), [Bing Search Transforms Replacement](https://docs.maltego.com/en/support/solutions/articles/15000060792-bing-search-transforms-replacement)
- **4.12.1 change**: the "Run All" action for Hub items / All Transforms was **removed** from context and run views (2026-07-20). [Desktop release notes](https://docs.maltego.com/en/support/solutions/articles/15000053036-release-notes-for-maltego-graph-desktop-)

### 1.6 Collections (Desktop)

Covered in the 08-12 note (threshold grouping, pin-out, partial selection). Additional detail from Options: two collection rules, the **neighbor rule** (A→[B..Z]) and the **chain rule** (paired 1:1 chains of same-type nodes under a common parent); the *ratio* (default 1.5) says how much later chains collect than neighbours (ratio 2 + limit 10 → neighbours at 10, chains at 20). Detail View exposes per-Entity "pinned" and "collection size" columns. [Options Menu](https://docs.maltego.com/en/support/solutions/articles/15000019182-options-menu), [Detail View](https://docs.maltego.com/en/support/solutions/articles/15000019236-detail-view)

### 1.7 Machines (Desktop)

- **What**: macros in the Maltego Scripting Language; run Transforms sequentially (`start{ run(); run() }`), in parallel (`paths{ … }`), or as parallel sub-pipelines (`path{ … } path{ … }`); pipeline carries only the previous step's output types; per-run `slider:N` and `"setting":"value"`; **user filters** (`userFilter(title, heading, description, proceedButtonText, icon, removePromptText, removePromptChecked, showIncomingLinks, showOutgoingLinks, selectEntities)`) pause for human pruning; **pipeline filters** `type() value() property() incoming() outgoing() degree() age() bookmarked()` with `scope:"global"|"local"`; actions `bookmark clearBookmark delete(parents,children) deleteBranch exportImage saveAs setLayout log status`. Feeders and triggers are documented as *not implemented*. CLI: `maltego --machine "<name> <type>=<value>"` with `-f` fullscreen, `-q` quit after, `-i#` iterations for perpetual machines. [Machines (Transform Macros)](https://docs.maltego.com/en/support/solutions/articles/15000019249-machines-transform-macros-), [Machine Syntax Reference](https://docs.maltego.com/en/support/solutions/articles/15000019254-machine-syntax-reference)
- **UI**: Machines tab → *Run Machine* wizard (pick machine, start parameter; "Show on startup / on empty graph" toggles), Machines window (status, countdown for perpetual machines), *New Machine* wizard, *Manage Machines* (clone/edit; hub-installed machines are read-only until cloned; the attack-surface blog walks through Clone → Edit → "Filter by input" Transform picker → **Format** and **Compile** buttons), *Stop All Machines*. **Perpetual machines** re-run every N seconds for monitoring. [Running a Machine](https://docs.maltego.com/en/support/solutions/articles/15000010786-running-a-machine), [New Machine](https://docs.maltego.com/en/support/solutions/articles/15000010788-new-machine), [Automating Attack Surface Assessments… Custom Machines](https://www.maltego.com/blog/automating-attack-surface-assessments-with-maltego-a-practical-guide-to-custom-machines/)
- **Pre-installed OSINT machines** (Standard Transforms Hub item): Company Stalker; Find Wikipedia Edits; **Footprint L1 / L2 / L3 / XXL**; Person - Email Address; URL to Network and Domain Information. **Third-party machines** shipped by Hub items: RiskIQ PassiveTotal (Certificate Explorer, Domain Analysis/Explorer, IP Analyzer/Explorer, SSL Enrichment, …), TinEye, ATT&CK–MISP (MISP Event to All), Have I Been Pwned (v3 alias/email, v5 pwned password), Farsight DNSDB Enumerate Domain. [Introduction to Maltego Machines](https://docs.maltego.com/en/support/solutions/articles/15000047415-introduction-to-maltego-machines)
- **Enterprise Machines** (Enterprise plan; needs the "Enterprise Machines" Hub item plus each machine's provider items): *Intelligence Gathering L1/L2 - Hashes [OSINT, Splunk]* (Abuse.ch URLhaus, AlienVault OTX, Intezer, Shodan, Splunk ES, VirusTotal Public; L2 adds AbuseIPDB, GreyNoise, Host.io, NIST NVD, SSL Certificate, WhoisXML), *Identify Relevant Threat Actors / Forum Threads [Intel 471]* (Phrase input), *Basic Digital Footprint [OSINT]* (Phrase; Standard Transforms + TinEye; prompts for relevance), *Full Identity Footprint [Pipl]* (Person/Alias/Email/URL). [Maltego Enterprise Machines](https://docs.maltego.com/en/support/solutions/articles/15000047414-maltego-enterprise-machines)
- **SDK**: `MaltegoMachine` ships raw DSL with a custom transform server (attributes `code, name, favorite, enabled, read_only, interactive, composite_entities, input_constraints`); "Machines are currently supported in Maltego Graph Desktop only." [Machines (SDK)](https://docs.maltego.com/en/support/solutions/articles/15000062348-machines-sdk-)

### 1.8 Import (Desktop unless stated)

## Part 2: Use cases and workflows (as Maltego documents them)

Each workflow is a numbered sequence with the Entities / Transforms / Machines the source names.
Transform display names are quoted as the source gives them; where a name has since been renamed by
the August 2025 search-engine migration I add the replacement in brackets. Blog-sourced steps are
Maltego-authored but older; Hub-item availability and plan gating change.

### W1. Infrastructure footprint of a domain (Level 1 → Level 3, manual and Machine)

The canonical Maltego data model: Domain → (TLD expand) → DNS Names (MX, NS, A) → IP addresses →
Netblocks → AS numbers → owning Company, then "back up the model" from netblocks via reverse DNS.
[How to Use Maltego Transforms to Map Network Infrastructure](https://www.maltego.com/blog/how-to-use-maltego-transforms-to-map-network-infrastructure-an-in-depth-guide/)

1. New graph → drag a **Domain** Entity from the palette, set its value. Optional first pivot: *To Domain [Find other TLDs]* to enumerate sibling TLDs. [Map Network Infrastructure](https://www.maltego.com/blog/how-to-use-maltego-transforms-to-map-network-infrastructure-an-in-depth-guide/)
2. Enumerate DNS names: *To Website [Quicklookup]* (www. prefix), *To DNS Name [Find common DNS Names]* (dictionary: mail, mx, ns, ftp, webmail, … imap), *To DNS Name [Attempt Zone Transfer]*, *To DNS Name - SOA*, *To websites using domain [Bing]* → now *To Website Using Domain [Search Engine]*, *To DNS Name [SecurityTrails]* and *To DNS Name (interesting) [SecurityTrails]* (VPN/webmail/firewall/test/scada/intranet/secure/ssh/database). Or run the whole "DNS from Domain" Transform Set with `>>` (set-level run, unconfirmed after 4.12.1; Part 3 item 9). Search-engine/passive-DNS results may be historical; verify. [Beginner's Guide L1 Part 1](https://www.maltego.com/blog/beginners-guide-to-maltego-mapping-a-basic-level-1-network-footprint--part-1/), [Bing Search Transforms Replacement](https://docs.maltego.com/en/support/solutions/articles/15000060792-bing-search-transforms-replacement)
3. Select all DNS Name / MX / NS Entities (they inherit from `DNSName`, so one Transform covers all) → *To IP Address [DNS]*. [Beginner's Guide L1 Part 2](https://www.maltego.com/blog/beginners-guide-to-maltego-mapping-a-basic-level-1-network-footprint--part-2/), [Machines (Transform Macros)](https://docs.maltego.com/en/support/solutions/articles/15000019249-machines-transform-macros-)
4. IPs → netblocks: *To Netblock [Using natural boundaries]* (default /24; size configurable via the spanner icon), *[Using routing info]* (BGP), *[Using WHOIS info]*. Validate blocks with *To DNS Names in netblock [Reverse DNS]* and manual inspection so "innocent by-standing" orgs are not swept in. [Map Network Infrastructure](https://www.maltego.com/blog/how-to-use-maltego-transforms-to-map-network-infrastructure-an-in-depth-guide/)
5. Netblocks → *To AS number* → *To Company [Owner]* (RIR data). Example result: `docs.maltego.com` hosted on AWS. [Beginner's Guide L1 Part 2](https://www.maltego.com/blog/beginners-guide-to-maltego-mapping-a-basic-level-1-network-footprint--part-2/)
6. Optionally go back up: AS → netblocks → reverse DNS for more hostnames. [Map Network Infrastructure](https://www.maltego.com/blog/how-to-use-maltego-transforms-to-map-network-infrastructure-an-in-depth-guide/)
7. **Automate**: select the Domain → Machines → *Footprint L1* (straight down the model), *Footprint L2* (adds shared-MX/NS domain discovery and same-IP websites, with **user filters** to drop hosted providers, for example deselect Google MX / Linode NS for paterva.com), *Footprint L3* (adds historical/reverse DNS on netblocks and *ToServerTechnologyWebsite*), *Footprint XXL* (SPF-record netblocks + reverse-delegated DNS; "have lots of RAM"). [Network Footprinting with Machines](https://www.maltego.com/blog/network-footprinting-with-machines-in-maltego/), [Running a Machine](https://docs.maltego.com/en/support/solutions/articles/15000010786-running-a-machine), [Introduction to Maltego Machines](https://docs.maltego.com/en/support/solutions/articles/15000047415-introduction-to-maltego-machines)
8. Layout/analysis: switch layouts and Views (Ball size by links, Diverse Descent) to spot outliers; use collection nodes on the large fan-outs. Expected output: hundreds of Entities (blog: >750 in under a minute for FP-L1 on one target). [Exploring Your Attack Surface](https://www.maltego.com/blog/exploring-your-attack-surface-with-maltego-a-practical-guide/), [Graph Sidebar](https://docs.maltego.com/en/support/solutions/articles/15000009615-maltego-graph-sidebar)

Pitfalls the sources name: slider caps results silently; L2/L3 user filters must be pruned or you
"follow the rabbit hole to Google's infrastructure"; Standard Transforms banner now says legacy-only
(Utilities Data Pass module carries the successors); Bing Transforms gone.

### W2. Attack-surface assessment and a custom Machine (extends W1)

1. Run *Footprint L1* on the target Domain.
2. Scope: select the target **Company** Entity → *Add Parents* repeatedly until the original Domain is in the selection → action bar *Copy To New Graph*.
3. On the Domain run *To DNS Name (interesting) [SecurityTrails]*; on the new DNS Names run *To IP Address [DNS]* (resolves ⇒ likely live).
4. Select IPs → *To Vulnerabilities [Shodan]*; on Netblocks → *To Vulnerable IP Addresses [Shodan]*.
5. Ports: *To Ports [Shodan Internet DB]*, *To Ports [OTX]*.
