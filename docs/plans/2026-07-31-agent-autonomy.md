# Agent autonomy — phased plan

The execution record of the wayfinder map
[Autonomous agent pipeline for birdbrain (#298)](https://github.com/thebristolsound/birdbrain/issues/298).
The confirmed design lives in the resolution of
[#299](https://github.com/thebristolsound/birdbrain/issues/299); the governance decision is
[ADR-0005](../adr/0005-unattended-agents-on-the-evidence-path.md).

**Destination:** the dispatch routine runs on its schedule, and a full week passes in which
the only human birdbrain work is issue triage and PR review.

## Standing rules (all phases)

- The dispatcher is a **scheduled cloud routine** — explicitly not a GitHub Action and not a
  local cron (decision 5 of #299).
- Strict-serial WIP: max one open agent PR; the routine exits without dispatching while one
  is open.
- Human review on every agent PR through the pilot; evidence-affecting PRs never auto-merge.
- Evidence gate per ADR-0005: `evidence-affecting` label at triage + path-list PR-diff
  backstop; Evidence impact section + known-answer test (or explicit justification) on every
  evidence-affecting PR.
- Give-up path: mis-specified issue → comment findings, relabel `needs-info`/`ready-for-human`,
  vacate the slot.
- PR attribution line exactly: `Pull request description generated by Claude Code`.

- [ ] Build the serial-slot dispatch routine, manually triggered: changes requested → address

      Includes the give-up path and the reviewer pre-pass
      ([#308](https://github.com/thebristolsound/birdbrain/issues/308)).
- [ ] Run remaining pilot cycles via manual triggers; track per-issue outcome toward the exit

      enable the cron ([#310](https://github.com/thebristolsound/birdbrain/issues/310)).
      Destination reached after the first full triage-and-review-only week.

## Phase 4 — widening (out of scope for this map)

Auto-triage routine, maintenance routines (dependency bumps, flaky-test detection), any
auto-merge decision, and promoting the background-job carve-out beyond this repo are all
deferred to a fresh effort once the pipeline is live, informed by real pilot data.

## Operational facts the pilot depends on

- Agent worktrees self-provision correctly once PR #318 lands; no Electron repair step
  belongs in any runbook. `mise trust` is granted per config-file path, so the pinned Node
  only applies once the tracked `.mise.toml` is trusted — every fresh clone or worktree
  location needs its own `mise trust` before the verify loop is reliable there.
- Known pre-existing flake: `tests/main/ipcHandlers.test.ts` "reports failure for the
  http/pipeline self-tests when the server is down" fails ~1-in-3 full parallel runs and
  passes on rerun. The dispatch routine should retry exactly this test once before treating
  the suite as red — or the flake should be fixed properly.
