Exporting Evidence

How to produce a self-contained, independently-verifiable evidence package from a case.

In this set: Overview Exporting evidence Verifying evidence

Export packages a case into a single evidence package — a self-contained ZIP that bundles the captured content, the signed audit manifest, the trusted-timestamp tokens, the public verification key, a human-readable report, a certification scaffold, and the by-hand verification runbook. The package is the artifact you hand to opposing counsel, a court, or an examiner; they can re-verify it with no Birdbrain installation. For the full picture of what each piece proves, read the Court Admissibility overview.

1. Before you export

1.1 Prerequisites

RequirementWhy
Operator name configured (Settings → Operator)Required. Export fails without it — the operator identity is recorded in the manifest entries and the certification. Set your real name, and ideally your role and organization.
A Time-Stamping Authority configuredDefaults to DigiCert (http://timestamp.digicert.com). Change it only if your engagement requires a specific TSA.
At least one capture in the caseAn export of an empty case produces a package, but with nothing to verify.

1.2 Let captures finish timestamping

Trusted timestamping is asynchronous and best-effort. A freshly captured page is pending until a background worker obtains its RFC 3161 token (on capture, on app start, and every 5 minutes). If trusted time matters for your matter, give captures time to move from pending to rfc3161 — and confirm a network connection to the TSA — before exporting.

The export is never blocked on trusted time

The export dialog runs a preflight and shows a warning like "N captures will export without RFC 3161 trusted time (X pending, Y none). Export will continue." The package still builds; unstamped captures are simply recorded as pending or none, and the report and certification say so explicitly. Exporting before stamping completes is a choice, not an error.

2. Producing the package

  1. Open the case you want to export and choose Export Case.
  2. Select what to include. Toggle the content sections (see §2.1) and, if the case has annotations, whether to burn them into the report screenshots.
  3. Enter the investigator name. This labels the report cover (it defaults to "Investigator" if left blank). It is distinct from the operator identity recorded in the manifest.
  4. Review the trusted-time warning, if shown, and decide whether to proceed now or wait for pending captures to stamp.
  5. Click Export and choose a save location. Birdbrain builds the ZIP, then appends a signed export record to the case's live audit manifest.

2.1 What the include options do

OptionEffect
CapturesAdds the capture log table (timestamp, title, URL, hash) to report.html. The captured .mhtml files are bundled regardless.
ScreenshotsEmbeds screenshots in report.html and ships each raw screenshot as a content-addressed, chain-bound screenshots/{sha256}.png artifact.
Audit trailRe-verifies every capture's integrity at export time (streams the MHTML, recomputes SHA-256, re-checks the manifest chain and sidecar hashes) and adds the integrity & trusted-time table to the report. The result is also recorded in the signed export entry (see §3.2).
Burn annotationsRenders pin annotations onto the report's screenshots for readability. This affects report.html only — the raw, chain-bound screenshot artifact is always the unmodified capture-time bytes.
Best practice

For an evidentiary export, enable Audit trail so the package carries a fresh, signed integrity verdict for every capture, and enable Screenshots so the visual record is both shown and independently hash-bound.

3. What is in the package

3.1 Package contents

The export is a single stored (uncompressed) ZIP:

FileRole
manifest.jsonlThe signed, hash-linked audit chain — the root of trust
signing-public-key.pemRSA public key that verifies every entry signature
tsa-ca-chain.pemTSA root + each token's embedded certificate chain
pages/{captureId}.mhtmlCaptured content (hashed as contentHash)
screenshots/{sha256}.pngRaw screenshots, content-addressed (hashed as screenshotHash)
timestamps/{captureId}.tstRFC 3161 tokens (DER), for stamped captures
report.htmlHuman-readable case report
certification.htmlFRE 902(13)/(14) supporting certification scaffold
evidence.jsonUnsigned convenience index — reconciled against the chain, not trusted on its own
VERIFY.mdStep-by-step by-hand verification runbook (stock tools, zero Birdbrain code)

3.2 Exports are themselves part of the audit trail

After the ZIP is written, Birdbrain appends a signed type: 'export' entry to the live case manifest. It records:

  • packageHash — SHA-256(canonicalStringify(sortedArtifacts)), committing to every packaged file's path, SHA-256, and size. It does not hash the final .zip or evidence.json (that would be circular).
  • verificationResult — the integrity tally from the audit-trail pass (total, verified, tampered, missing counts, and an overallValid flag that is true only when every capture verified).

This makes the act of producing evidence packages tamper-evident in the same chain as the captures. As a result, the manifest.jsonl inside the package is exactly one entry behind the live case manifest — by design, because packageHash is computed before its own export entry exists.

Failure handling

If the export entry cannot be appended (e.g. the signing key is unavailable), Birdbrain deletes the just-written ZIP rather than leave a package on disk without its corresponding, signed audit record.

4. Operator responsibilities for admissibility

The tool produces a verifiable package; a defensible record also depends on the operator:

  • Record a truthful operator identity. Name, role, and organization are self-asserted and flow into the certification; Birdbrain does not authenticate them.
  • Prefer stamped captures. Export after captures reach rfc3161 where trusted time matters; the preflight tells you how many are pending or none.
  • Preserve the original case. The export is a derived copy. Keep the working case directory and its live manifest intact.
  • Have counsel complete the certification. certification.html carries a [LEGAL WORDING TO BE SUPPLIED BY COUNSEL] banner; the operative sworn language for your jurisdiction and rule must be added by an attorney.
  • Deliver the package unmodified. Hand over the whole .zip. The recipient unzips it and verifies with the bundled VERIFY.md or the standalone binary — see Verifying evidence.
