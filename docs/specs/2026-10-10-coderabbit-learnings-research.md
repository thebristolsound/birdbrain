# CodeRabbit learnings: research

**Date:** 2026-10-10

**Question:** How does CodeRabbit's "learnings" feature create, store, scope, retrieve, apply, and prune review preferences, and how does it differ from the human-authored review configuration that sits beside it?

Research only. Sources are CodeRabbit's documentation, configuration schema, changelog, knowledge base, and blog, read on 2026-10-10. One section also cites CodeRabbit comments on this repository's pull requests as observed behavior; those citations are marked as observations, not documentation.

## Summary

A learning is a short natural-language review preference that CodeRabbit writes for itself, mostly from a chat reply to `@coderabbitai` on a pull request or issue, and stores in a database tied to the Git platform organization rather than in the repository. CodeRabbit rewrites the user's reply into a self-instructive sentence, records it with metadata (author, repository, file, pull request, source comment URL, timestamps, usage count), redacts credentials, and indexes it as a vector embedding. When CodeRabbit prepares a comment, it loads learnings within the configured scope (`local` for the repository, `global` for the organization, `auto` by repository visibility), treats file-pattern learnings as eligible only when a matching file changed, and applies a learning only when it judges it relevant to the changed code. A learning created on an open pull request stays confined to that pull request until it merges. People view, search, edit, and delete learnings in a web dashboard that tracks usage and last-used dates, through chat requests on a pull request, or through an Enterprise-only API; organizations can also hold new chat-sourced learnings for admin approval for up to 30 days. The documentation does not say that review comments cite the learnings they used, but CodeRabbit replies on this repository's pull requests carry a "Learnings used" block that quotes the full record. Path instructions in `.coderabbit.yaml` and code guideline files such as `CLAUDE.md` are the human-authored, versioned counterparts, and the documentation says path instructions take precedence over learnings.

## How a learning is created

- **Chat reply or mention.** A user creates a learning by stating a preference in natural language in a comment on a pull request or issue, typically a reply addressed to `@coderabbitai` on one of CodeRabbit's review comments ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- **The bot decides.** CodeRabbit "considers your reply, and decides to make a learning out of it"; a comment does not always produce one ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)). The documentation does not state the criteria for that decision.
- **Confirmation.** When CodeRabbit creates one or more learnings from a comment, it adds a collapsible section titled "Learnings Added" to its own reply ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)). On this repository's pull requests the section heading reads "Learnings added" and the section quotes the stored record and ends with the note "Learnings are effective only in the context of similar code segments" (observed in [Birdbrain PR 357](https://github.com/thebristolsound/birdbrain/pull/357#discussion_r3726451446)).
- **The stored text is a rewrite.** CodeRabbit stores "self-instructive text" that it composes from the reply, not the reply itself; the documented example turns a conversational reply into a one-sentence rule ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- **Explicit import from a file.** A comment such as `@coderabbitai add a learning using docs/coding-standards.md` makes CodeRabbit read the file and create corresponding learnings; the same mechanism imports an exported CSV ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- **Automatic inference.** The documentation refers to inferred learnings that the review pipeline creates automatically and that apply immediately to their source pull request even when approval is required ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)). The configuration overview says CodeRabbit builds learnings automatically from "your interactions with review comments over time" and that they capture patterns including "which types of suggestions your team typically accepts or rejects" ([Configuration overview](https://docs.coderabbit.ai/guides/configuration-overview)). What triggers an inferred learning is not documented.
- **No API creation.** The public API "does not create Learnings" and points to path instructions for durable guidance ([Learnings API](https://docs.coderabbit.ai/api-reference/learnings-list)).
- **Approval gate.** When `knowledge_base.learnings.approval_delay` is 1 to 30, CodeRabbit turns a new chat-sourced learning into a pending request instead of an active learning; admins approve or reject it, and it auto-approves at the deadline ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)). The changelog dates this feature to June 11, 2026 ([Changelog](https://docs.coderabbit.ai/changelog)).
- **Credential redaction.** On creation, import, approval, or admin edit, CodeRabbit replaces recognizable credentials with type markers such as `***REDACTED_GITHUB_TOKEN***` before storing the text and computing its embedding ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- **Documented authoring advice.** The documentation tells users to save team-wide patterns rather than one-off exceptions, to explain the reason behind a preference, and to reply on the specific line, because "a generic comment on the PR might produce a vague learning" while a line reply "produces a learning tied to that file pattern" ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).

## What a learning contains

- **Text.** The natural-language learning, called the description in the dashboard ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- **Metadata in the API.** The list endpoint returns `id`, `learning`, `organization_id`, `organization_name`, `repository_id`, `repository_name`, `author_id`, `author_username`, `file`, `source_url` ("URL of the PR comment where the learning was captured"), `pull_request`, `created_at`, `updated_at`, `usage_count`, and `last_used_at` ([Learnings API](https://docs.coderabbit.ai/api-reference/learnings-list)).
- **Dashboard fields.** The detail view shows description, usage, "Created by" (the user whose comment created the learning), repository, and the created, updated, and last-used dates ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- **Pending requests.** A pending learning also records source repository, source pull request when available, requester, request date, and auto-approval deadline ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- **Rendered form.** In comments on this repository the record renders as `Learnt from`, `Repo`, `PR`, `File` with a line range, `Timestamp`, and `Learning`; a learning meant to apply repository-wide still carried a file, with the range `0-0` (observed in [Birdbrain PR 357](https://github.com/thebristolsound/birdbrain/pull/357#discussion_r3726451446)). The documentation does not describe a line range field.
- **No explicit path-scope field.** Path scope comes from the file the comment was attached to; the documentation describes "a learning tied to a filename pattern" but does not document a separate glob or scope field that a user can set ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).

## Where learnings are stored and how far they reach

- **Storage location.** CodeRabbit keeps learnings in "an internal database that it associates with your Git platform organization" ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)). The delete endpoint names the stores: a canonical record in PostgreSQL, the LanceDB knowledge index, and "patterned-learning caches" ([Delete Learning](https://docs.coderabbit.ai/api-reference/learnings-delete)). Nothing is written to the repository.
- **Scope setting.** `knowledge_base.learnings.scope` takes `local` (only the reviewed repository's learnings), `global` (all of the organization's learnings in every review), or `auto`, the default, which uses only the repository's learnings for a public repository and all organization learnings for a private one ([Configuration reference](https://docs.coderabbit.ai/reference/configuration), [configuration schema](https://storage.googleapis.com/coderabbit_public_assets/schema.v2.json)).
- **Scope guidance.** The documentation recommends `local` for organizations with different stacks, because without it learnings about Python exception handling "might incorrectly influence React component reviews" ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)). It recommends `global` for consistent organization-wide standards ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- **Source pull request confinement.** On CodeRabbit SaaS, a learning created while a pull request is open applies only to that pull request; after the pull request merges "into any branch" its learnings become repository-wide, and closing without merging keeps them confined ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- **Approval delay level.** `approval_delay` can be set at the organization or repository level, from 0 to 30 days, default 0 ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings), [configuration schema](https://storage.googleapis.com/coderabbit_public_assets/schema.v2.json)).
- **Other surfaces.** The CLI documentation says paid users get "reviews powered by learnings from your CodeRabbit organization" when reviewing connected repositories ([CLI](https://docs.coderabbit.ai/cli/index)). A May 2025 blog post said learnings were organization-wide in the source-control integration and that per-developer learnings were planned ([How we built our AI code review tool for IDEs](https://www.coderabbit.ai/blog/how-we-built-our-ai-code-review-tool-for-ides)); whether per-user learnings shipped is not documented.

## How learnings are retrieved and applied

- **When.** "Every time CodeRabbit prepares to add a comment to a pull request or issue, it loads the learnings that apply based on your configured scope" and uses them "as additional context or instructions for its comment" ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- **Eligibility then relevance.** A file-pattern learning "becomes eligible when that pattern matches a changed file"; CodeRabbit "then evaluates the learning against the changed code and applies it only when it is relevant to that change." The page adds that "relevant path matches retain priority when CodeRabbit selects which relevant learnings to apply" ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)). The wording describes selection of a relevant subset, not injection of every learning. The documentation does not state the selection method, the number selected, or a token budget.
- **Vector index.** Each learning has a vector embedding, and the delete endpoint refers to "the vector used for review retrieval" ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings), [Delete Learning](https://docs.coderabbit.ai/api-reference/learnings-delete)). The update endpoint rebuilds "the shared review-index record and its embedding" ([Update Learning](https://docs.coderabbit.ai/api-reference/learnings-update)).
- **Retrieval cap for open pull requests.** "When Learnings retrieval is available, the source pull request can retrieve its 20 most recent source-scoped Learnings" ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)). No cap is documented for repository or organization retrieval.
- **Path matching.** File-pattern matching accepts paths with or without leading `./` or `/`, Windows separators, and files whose names start with a dot ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- **Verification against preferences.** A CodeRabbit blog post says verification agents filter candidate comments "against the code guidelines, configuration, and team preferences before review comments reach developers" ([Explainable AI Code Reviews in CodeRabbit](https://www.coderabbit.ai/blog/explainable-reviews-coderabbit-review-context-engine)). It does not say whether "team preferences" means learnings.
- **Citation in the review.** The documentation does not say that a review comment cites the learnings it used. The review summary's "Additional context used" entry lists code guideline files and path-based instructions, and the documentation describes no learnings entry there ([Code Guidelines](https://docs.coderabbit.ai/knowledge-base/code-guidelines)). CodeRabbit chat replies on this repository nevertheless include a collapsible "Learnings used" section quoting each applied learning with its source repository, pull request, file, and timestamp (observed in [Birdbrain PR 357](https://github.com/thebristolsound/birdbrain/pull/357#discussion_r3726451446)).
- **Usage accounting.** CodeRabbit counts each application: the dashboard shows usage count and last-used date per learning, an "Active" filter for learnings used in the last 30 days, and a "Never Used" filter ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)). The metrics dashboard reports "Learnings Usage" as the percentage of pull requests that benefited from learnings ([Git platform review metrics](https://docs.coderabbit.ai/guides/dashboard-metrics)).

## Viewing, editing, deleting, and pruning

- **Dashboard.** `app.coderabbit.ai/learnings` shows KPI cards (Total, Active, Never Used, Created This Week) and a table sortable by text, usage, last used, created, and updated; it filters by repository, file path, or user, and its search box runs a vector similarity search, so results need not contain the search words ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- **Web edit and delete.** The learnings page says users with the Admin role can edit or delete any learning in the dashboard, and CodeRabbit redacts credentials again on save ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)). The role table on the roles page gives Admin, Member, and Billing Admin all "Read/Write" on "Learning Resources (Web Interface)" ([Role-based access](https://docs.coderabbit.ai/management/roles)). The two pages disagree on whether a Member can edit in the web interface.
- **Chat edit and delete.** Any user can ask CodeRabbit in a comment to change or remove a learning, and the roles page says all users can manage learnings through pull request comments regardless of role ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings), [Role-based access](https://docs.coderabbit.ai/management/roles)). The original 2023 announcement says the bot "will remove any existing learnings that are no longer relevant" when told in chat ([Changelog](https://docs.coderabbit.ai/changelog)).
- **API.** Enterprise teams can update (`PATCH /v1/learnings/{learning_id}`) and delete (`DELETE /v1/learnings/{learning_id}`) with a user or workspace key holding `learning:write`; legacy organization keys and agentic keys cannot. Deletion is idempotent and removes the canonical record, the vector, and the caches ([Update Learning](https://docs.coderabbit.ai/api-reference/learnings-update), [Delete Learning](https://docs.coderabbit.ai/api-reference/learnings-delete)).
- **Approval queue.** Admins approve or disapprove pending learnings individually or in bulk on the "Pending approvals" tab ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- **Export and transfer.** The dashboard exports CSV, and the API exports JSON or CSV; moving to another account means committing the CSV to a branch, opening a pull request, and asking CodeRabbit to import it ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- **Pruning.** CodeRabbit does not document automatic expiry or pruning. The documentation recommends a manual quarterly review, deleting contradictory learnings, updating rather than accumulating, and checking learnings from inactive team members ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).

## Opt-out, privacy, limits, and failure modes

- **Opt-out.** `knowledge_base.opt_out` (default `false`) disables knowledge base features that need data retention and "removes any existing stored knowledge base data" ([Configuration reference](https://docs.coderabbit.ai/reference/configuration)). The overview warns that opting out "immediately and irrevocably removes all stored knowledge base data, including learnings." Stateless sources such as code guidelines keep working ([Knowledge Base overview](https://docs.coderabbit.ai/knowledge-base)).
- **Training.** CodeRabbit states it never uses customer code for model training, with or without data retention ([Knowledge Base overview](https://docs.coderabbit.ai/knowledge-base), [FAQ](https://docs.coderabbit.ai/faq)).
- **Retention period.** The FAQ lists learnings as "longer-lived review context" with an opt-out ([FAQ](https://docs.coderabbit.ai/faq)). A retention duration for learnings is not documented.
- **Redaction limits.** Redaction runs only at write time "and does not backfill or clean previously stored learnings" ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- **Documented limits.** `approval_delay` is 0 to 30 days; API writes share 10 requests per minute per organization; a list page holds up to 1,000 records and responses over 16 MB are rejected; file-path filters accept up to 10 paths ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings), [Learnings API](https://docs.coderabbit.ai/api-reference/learnings-list)). A maximum number of learnings or a maximum learning length is not documented.
- **Failure mode: learnings ignored.** CodeRabbit may keep making suggestions that contradict a learning "when the model deprioritizes certain learnings due to contextual overlap or conflicting instructions"; the documented workaround is a reinforcement instruction such as "Before responding, review all Learnings to ensure none are ignored" ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- **Failure mode: precedence.** The learnings page says path instructions take precedence over learnings, so a conflicting path instruction wins ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- **Failure mode: claimed but not stored.** With data retention off, CodeRabbit can reply that it stored a learning while storing nothing; the learning never appears in the dashboard and later reviews ignore it ([CodeRabbit knowledge base article](https://kb.coderabbit.ai/articles/1240714200-troubleshoot-learnings-do-not-appear-in-the-learnings-dashboard-after-coderabbit-says-it-stored-them)).
- **Failure mode: drift and contradiction.** The documentation warns that learnings can go stale and that "multiple conflicting learnings on the same topic can produce inconsistent behavior" ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- **Failure mode: cross-repository leakage.** Under `global` scope, or `auto` on a private repository, a learning from one repository can steer reviews of another with different conventions ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- **Failure mode: index out of step.** If an API update succeeds on the canonical record but the index refresh fails, the caller must repeat the request to rebuild the index ([Update Learning](https://docs.coderabbit.ai/api-reference/learnings-update)).
- **Failure mode: renamed repositories.** Stored historical repository names can differ after a rename, "so an empty result does not prove that no relevant guidance exists" ([Learnings API](https://docs.coderabbit.ai/api-reference/learnings-list)).

## Related features and how they differ

| Feature | Who writes it | Where it lives | Versioned in the repository |
| - | - | - | - |
| Learnings | CodeRabbit (from chat or inference) | CodeRabbit's database | No |
| `reviews.path_instructions` | People | `.coderabbit.yaml` or the web UI | Yes when in `.coderabbit.yaml` |
| Code guidelines | People | Files such as `CLAUDE.md` and `AGENTS.md` | Yes |
| `.coderabbit.yaml` | People | Repository root | Yes |

- **Path instructions.** `reviews.path_instructions` pairs a `minimatch` glob with instruction text of up to 20,000 characters, set in `.coderabbit.yaml` or the organization settings UI ([Configuration reference](https://docs.coderabbit.ai/reference/configuration), [Path-based review instructions](https://docs.coderabbit.ai/configuration/path-instructions)). The learnings page directs "formal, documented standards" here and keeps learnings for "incremental preferences that emerge during code reviews" ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)). A CodeRabbit blog post calls path filters and instructions highly deterministic, applied whenever the pattern matches ([Context Engineering](https://www.coderabbit.ai/blog/context-engineering-ai-code-reviews)), which contrasts with the relevance judgment applied to learnings.
- **A bridge from learned to versioned.** `@coderabbitai emit path instructions` gathers path-instruction suggestions from the past 7 days and opens a pull request that merges them into `.coderabbit.yaml` without overwriting existing entries ([Code review commands](https://docs.coderabbit.ai/reference/review-commands)). The documentation does not say whether learnings feed these suggestions.
- **Code guidelines.** CodeRabbit auto-detects files such as `**/AGENTS.md`, `**/CLAUDE.md`, `**/.cursorrules`, `.github/copilot-instructions.md`, `**/GEMINI.md`, `**/.windsurfrules`, and `**/.clinerules/*`, and applies each to its own directory and subdirectories unless an `applyTo` mapping says otherwise ([Code Guidelines](https://docs.coderabbit.ai/knowledge-base/code-guidelines)). The default list in the schema also includes `**/REVIEW.md`, which the documentation table omits ([configuration schema](https://storage.googleapis.com/coderabbit_public_assets/schema.v2.json)). Custom `filePatterns` "are added on top of the defaults" ([Code Guidelines](https://docs.coderabbit.ai/knowledge-base/code-guidelines)). Local guideline discovery is stateless, so opt-out does not affect it ([Code Guidelines](https://docs.coderabbit.ai/knowledge-base/code-guidelines)). The documentation tells users to use code guidelines, not learning import, for agent instruction files ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- **Guidelines are cited; learnings are not documented as cited.** The review summary lists every guideline file that reached the prompt under a "Code guidelines (N)" heading, labelled `configured`, `auto-discovered`, or `Agent Skill`, and reports skipped sources with a reason ([Code Guidelines](https://docs.coderabbit.ai/knowledge-base/code-guidelines)).
- **`.coderabbit.yaml`.** The repository-root file holds all of the above settings, including `knowledge_base.learnings.scope`, `approval_delay`, and `opt_out` ([Configuration reference](https://docs.coderabbit.ai/reference/configuration)). It controls how learnings are scoped and gated but holds no learning content.
- **Security Repository Learnings** are a separate store of accepted-risk guidance used by CodeRabbit Security scans, distinct from review learnings ([CodeRabbit glossary](https://docs.coderabbit.ai/reference/glossary)).

### This repository's configuration

This repository's `.coderabbit.yaml` sets `knowledge_base.code_guidelines` (enabled, with `filePatterns` that re-list `**/CLAUDE.md` and `**/AGENTS.md` and map `CONTEXT.md`, `SECURITY.md`, `docs/README.md`, and `docs/agents/writing-guide.md` to paths through `applyTo`). It sets nothing under `knowledge_base.learnings` and does not set `knowledge_base.opt_out`, so the defaults apply: `scope: auto`, which on a public repository such as this one means `local`, `approval_delay: 0`, and learnings enabled. The file's comment says a `filePatterns` array "REPLACES the built-in defaults"; the current documentation and schema say custom patterns supplement the defaults, so the comment is out of date ([Code Guidelines](https://docs.coderabbit.ai/knowledge-base/code-guidelines), [Configuration reference](https://docs.coderabbit.ai/reference/configuration)).

## Design properties worth copying

- Each learning carries its provenance (author, repository, file, pull request, and the URL of the comment that produced it), so a reader can trace any rule back to the conversation that created it ([Learnings API](https://docs.coderabbit.ai/api-reference/learnings-list)).
- CodeRabbit confirms creation in the same thread with a "Learnings Added" block that shows the stored text, so the person who taught it can see and correct a misreading at once ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- The stored text is a rewritten, self-instructive rule rather than the raw chat, and the documentation asks authors to include the reason so the rule generalizes correctly ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- Learnings tied to a file become eligible only when a matching file changes and then pass a relevance check, which keeps unrelated rules out of a given review ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- A learning made on an open pull request stays confined to it until the pull request merges, so abandoned work does not leak rules into other reviews ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- Usage count and last-used date per learning make dead entries visible through the "Never Used" and "Active" filters ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- An optional approval delay lets a maintainer review new entries before they take effect, with a deadline after which they apply anyway ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- Credentials are redacted before storage and before embedding, so a pasted secret does not become retrievable context ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- A documented precedence order (path instructions over learnings) settles conflicts between human-authored rules and learned ones ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).

## Known weaknesses

- Learnings live outside the repository, so they are not reviewed in pull requests, not visible in `git log`, and lost on opt-out "immediately and irrevocably" ([Knowledge Base overview](https://docs.coderabbit.ai/knowledge-base)).
- The bot decides whether a comment becomes a learning and what the rule says, and the criteria for inferred learnings are undocumented ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- The documentation admits that the model can ignore applicable learnings, and its workaround is a prompt instruction telling the model to reread them ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- No automatic expiry exists; staleness and contradictions are left to a manual quarterly review ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- Path scope comes from where the comment was attached rather than from a field the author sets, so a general rule can end up tied to one file ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings); observed `0-0` range in [Birdbrain PR 357](https://github.com/thebristolsound/birdbrain/pull/357#discussion_r3726451446)).
- The bot can report a learning as stored when data retention is off and nothing was saved ([CodeRabbit knowledge base article](https://kb.coderabbit.ai/articles/1240714200-troubleshoot-learnings-do-not-appear-in-the-learnings-dashboard-after-coderabbit-says-it-stored-them)).
- Broad scopes let a rule learned in one repository steer reviews in an unrelated one ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- The documentation does not specify how many learnings a review retrieves or how they are ranked beyond path-match priority, so a team cannot predict which rules a review saw except from the "Learnings used" block when one appears ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings)).
- The documentation contradicts itself on who may edit learnings in the web interface ([Learnings](https://docs.coderabbit.ai/knowledge-base/learnings), [Role-based access](https://docs.coderabbit.ai/management/roles)).
