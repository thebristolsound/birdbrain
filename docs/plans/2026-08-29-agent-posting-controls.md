# Agent posting controls: commit messages, PR bodies, comments

Date: 2026-08-29. Status: built on branch `t3code/agent-message-controls`; recorded as ADR-0022.

## Problem

Agents write commit messages, PR bodies and comments that are long and narrative, follow no
fixed structure, carry claims and identity the agent does not own (attribution trailers,
CodeRabbit summaries, statements about labels and CI), and get concatenated wholesale into the
squash-merge commit on `main`. The rules that exist are prose spread across `CLAUDE.md`,
`.claude/agents/*.md` and `.claude/skills/dispatch/SKILL.md`, with no mechanical check.

## Decisions

Every decision below was put to the maintainer and accepted with the recommended answer.

1. **Scope: every agent session in the repository.** Pipeline agents and interactive
   sessions post to the same surfaces for the same reader. Interactive sessions are bound by
   prose only during the experiment (decision 10).
2. **Squash message source:** the repository setting `squash_merge_commit_message` moves from
   `COMMIT_MESSAGES` to `BLANK`, and `squash_merge_commit_title` from `COMMIT_OR_PR_TITLE` to
   `PR_TITLE`. The dispatcher's merge call supplies `--subject "<PR title> (#n)"` and `--body`
   copied from the PR body's Summary section. A human merge types the body by hand from the
   same section. This is a repository setting no file records, so an ADR records it.
3. **Branch commit shape:** `<type>(<scope>): <subject>`, header at most 72 columns, an
   optional body of at most 6 lines wrapped at 72 columns that says why, no `Closes #N` (that
   line lives in the PR body), no `Co-authored-by` trailer of any kind.
4. **One PR body shape for humans and agents.** `.github/pull_request_template.md` becomes
   that shape; the agent's private five-section layout goes away.
5. **PR body sections, in order:** `Closes #N` as line 1; `## Summary` (at most 5 sentences);
   `## Changes` (one bullet per file group, no prose); `## Evidence-affecting` (`Yes` or `No`
   on one line, plus the four Evidence impact fields when Yes); `## Verification` (the
   `pnpm preflight` block verbatim, ADR-0018); the attribution line
   `Pull request description generated by Claude Code` as the last authored line. Hard cap of
   40 lines on everything outside the Verification block. Dropped: sections that walk
   through acceptance criteria with pasted test output, the "Handed to the dispatcher"
   paragraph (one line under Summary), Reviewer notes, Visual evidence unless the UI changed.
6. **Comment surfaces, all six shaped:** cycle claim and release (already shaped), pre-pass
   verdict (already shaped, 20-line cap), pre-pass full report (leaves the PR: written to a
   file or gist and linked from the verdict), review replies (one line per thread:
   `applied <sha>` or `not applied: <one sentence>`), give-up findings and defect filings
   (three fields: what, where as `file:line`, how to reproduce).
7. **Claims and identity:** `high_level_summary: false` in `.coderabbit.yaml`; the attribution
   line stays exactly as `CLAUDE.md` requires and the `claude[bot]` platform footer is
   tolerated; implementer rule 4 ("assert only actions you took and states you observed")
   extends to every comment; test output and coverage figures appear only inside the
   Verification block.
8. **Unit of enforcement: one skill per surface.** `.claude/skills/post-commit-message/`,
   `.claude/skills/post-pr-body/` and `.claude/skills/post-comment/`, each holding `SKILL.md`
   (the rule), `template.md` and `scripts/check.sh` (the linter). The hook that runs the
   linter lives in the agent's frontmatter (`hooks: PreToolUse`, matcher `Bash`), because a
   skill's own `hooks:` is only documented to fire when the skill is invoked, not loaded at
   agent start. An agent adopts a surface by listing the skill under `skills:` and adding the
   hook. The dispatch skill references `post-comment` for the comments it posts.
9. **First surface and agent:** PR body on `birdbrain-implementer`, with commit messages on
   the same agent because `commitlint` makes that nearly free. The reviewer and dispatcher adopt
   `post-comment` by reference (prose) in this change; their hooks come in a later iteration
   once the implementer hooks have held.
10. **Interactive sessions stay unbound** by hooks during the experiment. A `settings.json`
    hook that blocks the maintainer's own `gh pr create` is a different blast radius and comes
    after the skill has held on a few implementer PRs.
11. **Commit linter: `commitlint`.** `@commitlint/cli` and `@commitlint/config-conventional` as
    root `devDependencies`, config at `commitlint.config.mjs`, invoked from the hook as
    `pnpm exec commitlint --edit <file>`. The 6-line body cap and the forbidden-trailer rule
    are local plugin rules in the config file.
12. **Attribution at the source:** `"attribution": {"commit": "", "pr": "", "sessionUrl": false}`
    in the repository `.claude/settings.json`; the maintainer's global settings file moves
    from the deprecated `includeCoAuthoredBy` to the same key. The hook's forbidden-string
    check stays because claude-code issue #45137 reports the setting being ignored on one path.
13. **`includeGitInstructions: false`** in the repository settings file, so the skill's rule is
    the only commit and PR instruction the agent receives. Recorded in the ADR as an experiment
    variable so a change in commit behaviour has a named suspect.
14. **Output style at project scope:** `.claude/output-styles/plain-technical.md` (the user
    copy, with the Vale paths changed to the repository's `.vale.ini` and `.vale/styles/`) and
    `"outputStyle": "Plain Technical"` in `.claude/settings.json`, so cloud sessions, the
    doc-curator runner and every worktree get it. Whether `claude -p` applies `outputStyle`
    is unverified; the doc-curator's next dry run shows it.
15. **The project copy of the style is canonical for this repository.** The user copy serves
    other projects and may drift.

## Facts the decisions rest on

- Repository merge settings read on 2026-08-29: squash only, `squash_merge_commit_title =
  COMMIT_OR_PR_TITLE`, `squash_merge_commit_message = COMMIT_MESSAGES`.
- 11 of the last 30 commits on `main` carry a `Co-authored-by` trailer: two `Claude` trailers
  from `claude[bot]` cloud sessions, nine `Matt Donovan` trailers GitHub appends at squash time
  when a branch has a second author. Whether `BLANK` suppresses the latter is unverified.
- Claude Code 2.1.251 is installed; the `attribution` setting exists since 2.0.62.
- Agent frontmatter supports `hooks:` scoped to the subagent's lifetime and `skills:` preload.
  Skills bundle `template.md` and `scripts/` addressable as `${CLAUDE_SKILL_DIR}`.
- No off-the-shelf tool lints PR body section structure locally; GitHub has no required-section
  feature. `commitlint` (v21.2.2, 2026-08-13) lints a message file before any commit exists.
- The output style exists only at `~/.claude/output-styles/`; cloud sessions and runners read
  `.claude/` from the checkout and never see it.

## Files

Grouped as the commits they become, in order.

1. `chore(settings)`: `.claude/settings.json` (`attribution`, `includeGitInstructions`,
   `outputStyle`), `.claude/output-styles/plain-technical.md`. Outside the repository, no
   commit: `~/.claude/settings.json` key migration.
2. `chore(deps)`: `package.json`, `pnpm-lock.yaml`, `commitlint.config.mjs`.
3. `feat(skills)`: the three skill directories, each with `SKILL.md`, `template.md`,
   `scripts/check.sh` and a `scripts/test-check.sh` that runs the linter over pass and fail
   fixtures.
4. `docs(agents)`: `.claude/agents/birdbrain-implementer.md` (frontmatter `skills:` and
   `hooks:`; the duplicated commit and PR-body prose replaced by a pointer; rule 4 widened),
   `.claude/agents/birdbrain-reviewer.md` (pointer to `post-comment`),
   `.claude/skills/dispatch/SKILL.md` (merge call with subject and body, full report off the
   PR, reply shape, pointer to `post-comment`), `CLAUDE.md` (pointer lines only).
5. `docs(templates)`: `.github/pull_request_template.md` rewritten to decision 5;
   `.coderabbit.yaml` `high_level_summary: false`.
6. `docs(adr)`: `docs/adr/0022-<slug>.md` recording the repository setting change, the
   experiment scope and its variables; this plan.

The repository setting change (decision 2) is one `gh api -X PATCH` call, run at build time
after the go, and recorded in the ADR with the before and after values.

## Verification

- `pnpm preflight` green at head (lint, typecheck, tests, build, coverage).
- Each `scripts/test-check.sh` passes: the commit linter rejects a 7-line body, a `Closes`
  line and a `Co-authored-by` trailer, and accepts a conforming message; the PR-body linter
  rejects PR #1117's body (walkthrough sections, over the cap) and accepts the template filled
  in; the comment linter rejects a 21-line verdict and accepts a 20-line one.
- The hook fires inside the implementer: a dry spawn with a deliberately bad commit message is
  blocked with the linter output on `stderr`.
- `gh api repos/thebristolsound/birdbrain --jq '{squash_merge_commit_title,
  squash_merge_commit_message}'` shows `PR_TITLE` and `BLANK`.

## Out of scope, filed separately if found

Hooks for the reviewer and dispatcher comment surfaces, a `settings.json` hook binding
interactive sessions, and a CI check on `agent-authored` PR bodies are all deferred by
decisions 9 and 10 and get their own issue once the experiment reports.
