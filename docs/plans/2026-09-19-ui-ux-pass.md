# UI and UX pass, 2026-09-20

What a driven pass over the running app found, screen by screen. Each screen has one section, each finding one row. Nothing here is filed, fixed or scheduled.

The app under test was built from `main` at d48ab3fa and run from the sweep worktree `/home/matt/.t3/worktrees/birdbrain/sweep-ui` on 2026-09-20.

## What was driven

Playwright drove the built Electron app under `Xvfb`, one spec per screen, 11 screens: app shell, Dashboard, Case Overview, Captures, Signals, Notes, Data explorer, Settings, the Chrome extension install surfaces, the New Case wizard and Export. Each screen's primary states were driven in four theme and density combinations (light and dark, compact and comfortable) where the state could be reached in all four; secondary states were driven in light and compact only, and each section's coverage sentence says which. Every spec watched `console` and `pageerror` for the whole run. Accessibility numbers come from axe-core in legacy mode, run per theme per state.

## What was not driven

The Chrome extension's own surfaces - popup, options page, context menu, in-page toast and selection bar - are Chrome surfaces that this Electron harness cannot reach, so the extension section covers only the in-app install banner and walkthrough. Native dialogs are the other hole: `dialog.showOpenDialog` and `dialog.showSaveDialog` open an operating-system modal with no window under `Xvfb`, so Browse, Upload, Create Backup, Restore from File, Export Table and the real save picker were exercised only as far as their trigger, or with the dialog stubbed in the main process. The runs have no network by design, so archive.org snapshot queries, updater states and trusted-time stamping all fail closed.

## Where the scripts and artefacts live

The recipe is `e2e/.sweep/README.md` in the sweep worktree. Screen specs are `e2e/.sweep/<screen>.spec.ts`; refuter specs are `e2e/.sweep/refute-<screen>-<n>.spec.ts`. Structured dumps are written to `e2e/.sweep/results/<screen>-data/` and screenshots to `e2e/.sweep/shots/`.

Screenshot and artefact paths in this page are relative to the sweep worktree root, and none of them are tracked: `.gitignore` excludes `e2e/.sweep/`, so the images and dumps exist only on the machine that ran the pass. That is stated here once; the tables cite the relative path alone.

## App shell: TopBar, Sidebar, command palette, onboarding tour

Coverage: `e2e/.sweep/shell.spec.ts`, six tests, green in one run. ## How to re-run

Start from `e2e/.sweep/README.md` in the sweep worktree: it holds the proven command (a private network namespace with loopback up, `xvfb-run`, and `npx playwright test` against the already-built app), the fixture import, the seeding helpers to copy from `e2e/case-overview.spec.ts`, the theme and density switches, the screenshot convention and the axe legacy-mode requirement. Do not rebuild or reinstall; the worktree is already built and its native dependency is already rebuilt for Electron. To re-drive one screen, run its spec: `e2e/.sweep/shell.spec.ts`, `dashboard.spec.ts`, `overview.spec.ts`, `captures.spec.ts`, `signals.spec.ts`, `notes.spec.ts`, `data.spec.ts`, `settings.spec.ts`, `extension.spec.ts`, `wizard.spec.ts` and `export.spec.ts`, each with `--output=e2e/.sweep/results/<screen>` so Playwright's own cleanup does not take the dumps with it. The refuter specs, `refute-<screen>-<n>.spec.ts`, re-drive one finding each and are the shortest way back into a disputed row.
