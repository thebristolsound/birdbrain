# shadcn Tabs + Skeleton Migration — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add shadcn's `Tabs` and `Skeleton` primitives at shadcn defaults and migrate two surfaces that benefit measurably: SettingsView's hand-rolled nav (gains Radix keyboard/ARIA) and three loading-state placeholders (replace `"Loading..."` text with skeleton blocks).

**Architecture:** Coexist-only. The existing customized `ui/*` layer (Button/Card/Badge/Input/Textarea/Label/Dialog/ScrollArea — styled with Birdbrain tokens like `bg-accent`, `neu-card`) is **not** modified. New primitives are added at shadcn defaults via the official CLI. The token bridge already in `globals.css` makes shadcn-default class names (`bg-card`, `text-muted-foreground`) render in the Birdbrain look.

**Tech Stack:** shadcn (`shadcn@^4.5.0` already in devDeps), Tailwind v4 (`@theme` blocks in `src/renderer/styles/globals.css`), React 19, Radix UI primitives (added per-component by the CLI), Vite via electron-vite.

## Pre-flight context (read before starting)

**Discovered state of the codebase:**
- `shadcn@4.5.0` is installed in devDeps but there is no `components.json` at the repo root.
- `src/renderer/components/ui/` contains **customized** stubs (Button, Card, Badge, Input, Textarea, Label, Dialog, ScrollArea) styled with Birdbrain tokens. **Do not overwrite these.** They are imported by 38 files.
- `src/renderer/lib/utils.ts` already exports `cn()`.
- `src/renderer/styles/globals.css` has a "shadcn token bridge" block (lines 59–75) mapping Birdbrain semantic tokens to shadcn's expected names (`--color-background`, `--color-foreground`, `--color-primary`, etc.). This bridge lets new shadcn-default components render in the Birdbrain look without immediate visual conflict.
- Path aliases: `@renderer/*` → `src/renderer/*`, `@shared/*` → `src/shared/*`.
- Test runner: vitest under Electron (`pnpm test`).

**What was deliberately cut from the original plan:**
- `Table` primitive + SelectorTable migration. The shadcn `Table` is a thin semantic wrapper over `<table>` — no UX, accessibility, or DX gain over what's already there.
- "Arc B" reset of existing customized primitives to shadcn defaults. Trading Birdbrain's indigo/neumorphic identity for the generic shadcn neutral look is a net negative for an OSS forensic tool, and the 38 consumers depend on custom sizes (`xs`, `icon-sm`) and a custom `accent` Badge variant that wouldn't survive the reset.

**The two real wins kept:**
1. **Tabs in SettingsView** — current nav is hand-rolled `<button>` elements with no ARIA roles or keyboard navigation. Radix Tabs gives `role="tablist"`, `role="tab"`, `aria-selected`, and arrow-key cycling for free.
2. **Skeleton for loading states** — replaces text fallbacks like `"Loading case..."` with proper layout-preserving skeleton blocks.

**Out of scope:**
- Replacing `CaseWorkspace` routed tabs with non-routed `<Tabs>` (would lose deep-linking).
- Any change to Button/Card/Badge/Input/Textarea/Label/Dialog/ScrollArea.
- Any change to `globals.css` (the token bridge stays as it is).

### Task 1: Initialize shadcn CLI configuration

**Files:**
- Create: `components.json`

- [ ] **Step 1: Create `components.json` at repo root**

The CLI normally writes this via `pnpm dlx shadcn@latest init`, but `init` will also try to overwrite the existing customized `lib/utils.ts` and add a default theme block. To avoid that, write `components.json` by hand:

```json
{
  "$schema": "https://ui.shadcn.com/schema.json",
  "style": "new-york",
  "rsc": false,
  "tsx": true,
  "tailwind": {
    "config": "",
    "css": "src/renderer/styles/globals.css",
    "baseColor": "neutral",
    "cssVariables": true,
    "prefix": ""
  },
  "aliases": {
    "components": "@renderer/components",
    "utils": "@renderer/lib/utils",
    "ui": "@renderer/components/ui",
    "lib": "@renderer/lib",
    "hooks": "@renderer/hooks"
  },
  "iconLibrary": "lucide"
}
```

The empty `tailwind.config` is correct — Tailwind v4 has no JS config; the CLI knows to skip it when the field is empty.

- [ ] **Step 2: Verify the CLI accepts the config**

Run: `pnpm dlx shadcn@latest diff` from the repo root.
Expected: prints `"No components found."` or lists existing components without errors. A `"components.json invalid"` error means the file shape is wrong — fix before proceeding.

### Task 4: Migrate SettingsView vertical nav to Tabs

**Files:**
- Modify: `src/renderer/components/settings/SettingsView.tsx`

**Why this is the headline win:** SettingsView already uses `useState<SettingsTab>` for selection — a non-routed pattern that maps cleanly to `<Tabs orientation="vertical">`. The current nav is plain `<button>` elements with no `role="tablist"`, no `role="tab"`, no `aria-selected`, and no keyboard arrow-key handling. Radix Tabs supplies all of that.

- [ ] **Step 1: Read the full current file**

Read `src/renderer/components/settings/SettingsView.tsx` end-to-end. Confirm the file ends with the `</nav>` + content panel + closing `</div>` and contains no extra logic (footer, modal, side-effect) that the rewrite below would lose. If extra logic exists, preserve it in the rewrite.

- [ ] **Step 2: Replace the nav with Tabs**

Rewrite `src/renderer/components/settings/SettingsView.tsx`:

```tsx
import { useState, useEffect } from 'react'
import type { BirdbrainSettings } from '@shared/types'
import { AIConfig } from './AIConfig'
import { CapturePreferences } from './CapturePreferences'
import { StorageConfig } from './StorageConfig'
import { AppearanceConfig } from './AppearanceConfig'
import { OperatorConfig } from './OperatorConfig'
import { About } from './About'
import { Key, Camera, HardDrive, Palette, Info, UserCircle, Database } from 'lucide-react'
import { DatabaseAdmin } from './DatabaseAdmin'
import { Tabs, TabsList, TabsTrigger, TabsContent } from '@renderer/components/ui'

type SettingsTab = 'ai' | 'capture' | 'storage' | 'appearance' | 'operator' | 'database' | 'about'

const settingsTabs: { id: SettingsTab; label: string; icon: typeof Key }[] = [
  { id: 'ai', label: 'AI', icon: Key },
  { id: 'capture', label: 'Capture', icon: Camera },
  { id: 'storage', label: 'Storage', icon: HardDrive },
  { id: 'appearance', label: 'Appearance', icon: Palette },
  { id: 'operator', label: 'Operator', icon: UserCircle },
  { id: 'database', label: 'Database', icon: Database },
  { id: 'about', label: 'About', icon: Info }
]

export function SettingsView() {
  const [settings, setSettings] = useState<BirdbrainSettings | null>(null)
  const [activeTab, setActiveTab] = useState<SettingsTab>('ai')

  useEffect(() => {
    window.birdbrain.settings.get().then(setSettings)
  }, [])

  useEffect(() => {
    window.birdbrain.settings.update({ lastActiveSection: 'settings' })
  }, [])

  const handleUpdate = async (partial: Partial<BirdbrainSettings>) => {
    const updated = await window.birdbrain.settings.update(partial)
    setSettings(updated)
  }

  if (!settings) return <div className="text-text-muted">Loading settings...</div>

  return (
    <Tabs
      value={activeTab}
      onValueChange={(v) => setActiveTab(v as SettingsTab)}
      orientation="vertical"
      className="flex h-full"
    >
      <nav className="w-48 shrink-0 border-r border-border p-3">
        <TabsList className="flex h-auto w-full flex-col gap-1 bg-transparent p-0">
          {settingsTabs.map(({ id, label, icon: Icon }) => (
            <TabsTrigger
              key={id}
              value={id}
              className="w-full justify-start gap-2 px-3 py-2 data-[state=active]:bg-accent-subtle data-[state=active]:text-accent data-[state=active]:font-semibold"
            >
              <Icon size={16} />
              {label}
            </TabsTrigger>
          ))}
        </TabsList>
      </nav>

      <div className="flex-1 overflow-auto p-6">
        <TabsContent value="ai" className="mt-0">
          <AIConfig settings={settings} onUpdate={handleUpdate} />
        </TabsContent>
        <TabsContent value="capture" className="mt-0">
          <CapturePreferences settings={settings} onUpdate={handleUpdate} />
        </TabsContent>
        <TabsContent value="storage" className="mt-0">
          <StorageConfig settings={settings} onUpdate={handleUpdate} />
        </TabsContent>
        <TabsContent value="appearance" className="mt-0">
          <AppearanceConfig />
        </TabsContent>
        <TabsContent value="operator" className="mt-0">
          <OperatorConfig />
        </TabsContent>
        <TabsContent value="database" className="mt-0">
          <DatabaseAdmin />
        </TabsContent>
        <TabsContent value="about" className="mt-0">
          <About />
        </TabsContent>
      </div>
    </Tabs>
  )
}
```

Notes:
- `data-[state=active]:*` selectors preserve the existing accent-subtle highlight on the selected tab.
- `mt-0` on each `TabsContent` overrides the shadcn default top margin (which assumes horizontal layout).
- `<Tabs className="flex h-full">` replaces the original outer `<div className="flex h-full">`.
