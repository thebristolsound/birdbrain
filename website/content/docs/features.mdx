This page lists what Birdbrain does on its main branch. A feature merged since the newest
release ships with the next one. The [screenshot tour](/docs/screenshots)
shows each screen, and the [threat model](/docs/threat-model) says what the integrity controls
prove and what they do not.

## Capture

- Capture the current page from the extension popup or the right-click menu. A capture records
  the MHTML, a stitched full-page screenshot, the page text, response headers, HTTP status, the
  final URL, and the browser, user-agent, and extension versions.
- Use scrolling capture for pages that load content as you scroll. It scrolls for up to two
  minutes and stops when the page stops growing.
- Select text on a page to create a selector, add a tag, or save a quote. Tagging or quoting a
  page the case does not hold yet captures it first.
- After a capture, a card on the page confirms the hash was recorded, and offers tagging,
  recapture, and a link to the capture in the app.
- Paste a list of URLs and the desktop app captures them in a hidden window. The app labels these
  captures as background captures, warns when a page shows a login wall, and blocks cookie
  banners using consent filter lists.
- Before a background capture saves the page, it scrolls to load content that appears on
  scroll. The capture's signed manifest entry records whether the scroll ran and how it ended:
  nothing to scroll, the page stopped growing, the page reached the height limit, or the time
  limit ran out. It also records the last page height read and whether the scroll lifted the
  page's scroll lock.
- Before it saves the page, a background capture pins each image the page displayed from a set
  of sources to the one it displayed. The browser's page saver drops the `srcset` attribute, so
  without this an image offered only through `srcset` would be missing from the saved page, and
  one that also has a `src` would be filed under that address. An image offered as a set is an
  `img` element with a `srcset`, or a `picture` element with `source` elements; the saver keeps
  the second, so only an `img` outside a `picture` is pinned.
- The capture first gives those images up to 5 seconds to finish loading or fail, and then takes
  the screenshot. It then pins each one that displayed an image, loaded with a natural width and
  height above zero: it sets the image's `src` to the address the browser loaded it from, removes
  its `srcset` and `sizes`, and waits up to 5 seconds for the pinned images. Both waits use only
  time left before the capture's final steps. The Transaction Record keeps recording until the
  pin is done, so any request it causes is in the record.
- The signed entry records how many images were pinned, and how many of those were still loading
  their pinned source, or had failed to, when the second wait ended. The counts cover only images
  that had settled and displayed an image before the pin. An image still loading after the first
  wait, one that failed to load, and one shown from a `blob:` address are left as they are and
  not counted, so the saved page lacks any of them offered only through `srcset`. A `blob:`
  address is left alone because loading it again fails once the page has revoked it. An image the
  page has not started loading, such as a lazy image below where the scroll stopped, holds the
  first wait to its end. Pinning reaches only the page's own document: an image in a frame or a
  shadow root is not pinned.
- An image whose `srcset` density or `sizes` set its size, with no `width` and `height` of its
  own, shows at its file's natural size in the saved page and the PDF, so either can differ from
  the screenshot. When that density makes the natural size smaller than one pixel, the image
  counts as not displayed and is left as it is.
- A background capture's signed manifest entry lists the files the capture holds and why any
  is missing. For the screenshot it records the page size, the image size, and whether the
  image was scaled down, cut short, or had trailing blank space trimmed.
- A background capture also saves a Transaction Record: a WARC file of the requests and
  responses the browser reported while it loaded the page, those of frames from other sites and
  of the page's workers and service workers included, until just before the page is saved. The
  signed entry holds the file's SHA-256 hash and counts what the record lacks: responses from the
  cache, failed, cancelled, and unfinished requests, requests the browser reported finished with
  no response, and bodies it left out, such as one over 10 MB. If recording fails, for example
  because the page made more requests than the record holds, Birdbrain still saves the capture,
  and its entry says the record is missing.
- The Transaction Record replaces the values of the `Cookie`, `Set-Cookie`, `Authorization`, and
  `Proxy-Authorization` headers with `[value replaced by Birdbrain]` and keeps the header names.
  A token in a URL, in a request or response body, or in any other header stays in the record,
  so an export of a signed-in page can still hold a reusable credential.
- The record stores each body without its content encoding, and keeps the headers that described
  the encoding as `x-orig-content-encoding`, `x-orig-transfer-encoding`, and
  `x-orig-content-length`.
- The record shows nothing for a resource the page used a second time without a new request, for
  the requests of a shared worker, or for what runs below a frame or worker whose setup failed.
  The hidden window loads a blank page first, so the page sees one more `history.length` entry
  than a direct visit gives it.
- For an HTTPS page, the signed entry records the TLS details the browser reported for the main
  document: protocol, cipher, certificate subject, alternative names, issuer, and validity. They
  are the browser's summary of the connection and hold no certificate bytes, and they are kept
  apart from the certificate chain Birdbrain fetches after the capture.
- A background capture also saves a PDF of the page, on Letter-size pages. Birdbrain prints it
  last, after the screenshot, the saved page, and the Transaction Record, so a file the page loads
  only for printing is not in the record. The signed entry holds the PDF's SHA-256 hash and states
  that the PDF was printed after recording stopped. The PDF shows the page after image pinning,
  which can make it taller than the screenshot shows. If the page, measured when it is printed,
  is taller than 50,000 pixels, the PDF is larger than 100 MiB, printing fails or runs out of
  time, or the page moves to another address after it is saved, Birdbrain still saves the
  capture, and its entry says the PDF is missing. The capture keeps the address and title of the
  page it saved.
- Recapture one page or a selection. The new capture links to the earlier one, which stays in
  the case.
- Exclude URLs by substring, wildcard, or regular expression. Exclusions apply to all cases or
  to one case.
- Birdbrain removes its own page UI before taking the snapshot, and aborts the capture if it
  cannot.

## Cases

- Create a case with a wizard that offers starter selectors for email addresses, crypto
  addresses, IP addresses, domains, phone numbers, and usernames.
- The case overview shows changes since your last visit, recent captures, an activity timeline,
  an integrity summary, top sources, quick notes, tags, selectors, and a link map.
- Filter the capture list by text, format, date, tag, or favourite, and act on a selection in
  bulk: tag, favourite, recapture, export, or delete.
- View each capture as a screenshot, as the archived page with scripts turned off, as extracted
  text, or alongside Wayback Machine snapshots.
- Write notes in a rich-text editor. `@` links captures and notes, and `#` links selectors and
  tags.
- Annotate screenshots with rectangles, arrows, highlights, redaction boxes, and numbered pins.
  The original screenshot stays unchanged, and the report in an export can show the
  annotations.
- Birdbrain assigns exhibit numbers to captures and cites them in exports.
- Search the text of every capture in a case.
- Search also finds link targets, the alt text of images inside links, image addresses, tracking
  codes, and cryptocurrency addresses in a stored page, email and web addresses written in a page's
  text, and fourteen mail header fields in a block of header lines in that text, such as `From`,
  `To`, `Cc`, `Reply-To`, `Message-ID`, `References`, and a Usenet `Path`. Each result names its
  exhibit and the first 12 characters of its content hash. A header result opens the capture's
  **Text** tab with the value marked, unless the text there has changed since it was indexed. An
  email or web address from the text opens the same way. A link result opens the **Links** tab and
  marks the rows with that link target, or for alt text the rows whose text is that alt text. An
  image address, tracking code, or cryptocurrency address opens the **Links** tab too, and marks no
  row. When the page lists links, the tab says when none of them matches, and an older plain HTML
  capture has no link list.
  If a capture's content hash changed after it was indexed, its link and header matches are listed
  as unavailable instead.
- Check a search result for a link target, image alt text, or mail header against the stored
  capture. The check says whether the recorded text is present at its place in the stored page or
  extracted text, absent there, or cannot be checked, and why. It does not show whether what the
  page says is true.

## Analysis

- Birdbrain extracts indicators from every capture and lists the pages each one appeared on:
  - IPv4 (public only) and IPv6 addresses, domains, email addresses, MAC addresses, and ASNs
  - MD5, SHA-1, SHA-256, and SHA-512 hashes, and CVE identifiers
  - Bitcoin, Ethereum, and Monero addresses
  - Google Analytics, AdSense, Tag Manager, and Ads IDs, and Facebook Pixel IDs
  - X, Facebook, Instagram, LinkedIn, YouTube, GitHub, and Telegram accounts
  - `.onion` and `.i2p` addresses
- Selectors flag exact text or a regular expression across every capture in the case,
  including captures made before the selector existed. Matches export as CSV.
- The Data screen lists every file in a case with its properties, extracted text, headers,
  TLS details, and manifest entries, and verifies any branch of the tree. Local files can be
  staged and then added to the evidence record or discarded.
- Indicators have their own group in the Data screen's rail, with an entry for each category
  and subcategory. Picking one in the rail or in the indicator browser selects it in both.
- Unreviewed Captures, under Views in the Data screen's rail, lists the captures that no note
  names and no selector matched. It groups them by the `From` and `Reply-To` addresses of mail
  headers in their text, by link host, and by email addresses and accounts found in at most two
  captures of the case, a number you can change in the view. A capture under a header or link
  opens with that header or link marked, as a search result does; one under an address or
  account opens the capture. The view reads the case again each time it opens, so a capture
  that a note now names or a selector now matches is no longer listed.
- Look up a page on the Internet Archive, pin snapshots to the case, and compare a snapshot side
  by side with your capture.

## Integrity

- Birdbrain hashes the MHTML, screenshot, extracted text, Transaction Record, and PDF separately
  with SHA-256.
- Each case keeps an append-only, hash-chained manifest signed with an RSA-2048 key. The key is
  a file encrypted through the operating system's credential store when one is available. Without
  one, Birdbrain asks you to accept storing the key as plain text. Birdbrain decides this once,
  when it creates the key.
- RFC 3161 timestamps come from DigiCert by default. The authority is configurable, and
  timestamping can be turned off.
- After each HTTPS capture, Birdbrain fetches the site's TLS certificate chain and records it in
  the signed entry as corroboration. If the fetch fails, the entry has no chain.
- Re-verify a capture, a branch of the case, or the whole manifest from inside the app.

## Export

- Export an evidence package as a full bundle or as a court exhibit without notes. Each preset
  can be adjusted, and an export can cover only selected captures.
- An evidence package contains an HTML report, the captures, their screenshots, Transaction
  Records, and PDFs, the signed manifest, the public key, the timestamp tokens and authority
  chain, `VERIFY.md`, and a `verify.sh` script.
- Export a working copy for your own use. A working copy is not an evidence package: it has no
  certification, no signed manifest, no signing key and no verification material, and it cannot be
  verified.
- Download a single capture as MHTML, a PDF report, or a PNG screenshot.
- Export a tag's captures as an evidence package, or copy them to the clipboard as Markdown.
- Move a case to another machine as a `.birdbrain` archive. Import verifies the archive first
  and always creates a new case.

## App

- Updates arrive on a stable or beta channel. Birdbrain never restarts on its own to install
  one.
- The command palette (`Ctrl+K`) switches and creates cases, replays the walkthrough, and opens
  a problem report.
- Choose a dark or light theme, one of three density settings, and reduced motion.
- First launch opens a guided tour, an extension setup guide, and a demo case. Exports from the
  demo case are marked as demo material.
- Create personas, the research identities you browse as, and import their cookies. Captures do
  not use a persona yet.
- Problem reports stay local until you send them. The app also includes a log viewer and a
  capture pipeline self-test.
- Database tools cover backup and restore, snapshots before upgrades, vacuum, and search index
  rebuilds.

## Limits

This is beta software. Use synthetic or low-stakes material where you can, and export anything
you cannot afford to lose.

- You capture each page yourself. Automatic capture while you browse is turned off in this
  beta, and Birdbrain does not save video.
- A case belongs to one investigator on one machine. You can move a case to another machine as
  an archive file.
- Birdbrain does not encrypt the database or capture files at rest. Confidentiality of the
  stored case relies on your operating system's full-disk encryption.
- The signing key is a file encrypted through the operating system's credential store. On a
  machine without one, Birdbrain asks you to accept storing the key as plain text. Birdbrain
  decides this once, when it creates the key.
- Deleting a capture removes its files, but its URL, capture time, and hashes stay in the
  append-only manifest and appear in exports that include the audit trail.
- Redaction boxes hide text only in the report. The evidence package still contains the
  original screenshot and the full saved page.
- Capture details show the result of the last verification run, not the state of the file now.
  Click **Re-verify** for a current result.
- Export is the only backup that includes capture files. The in-app database backup copies the
  database alone.
- You can create personas and import their cookies, but captures do not use a persona yet.
- The extension runs in Chrome and Chromium only.
- Data formats may change between beta releases.

## Network use

Birdbrain makes these outbound connections:

- the capture's hash, never its content, to the timestamp authority
- the captured site, once more, to record its TLS certificate
- the target site, when you paste URLs or recapture. The desktop app loads the page itself,
  from your IP address, with a user agent that names Birdbrain
- the Internet Archive, when you ask for a lookup
- the filter list host, to download cookie-banner lists
- GitHub, to check for updates
- for Shared Case sync, once you share or join a Case: a relay (n0's public relays by default,
  or one you host), each teammate's machine, a listening port for teammates to reach you, and
  port-mapping requests to your router. Sync does not use the Egress setting, so the relay and
  your teammates see your IP address, and a teammate can learn every interface address on your
  machine, not only the public one

[SECURITY.md](https://github.com/thebristolsound/birdbrain/blob/main/SECURITY.md) lists the
fixed hosts. If you work through a VPN or Tor, route the whole machine through it.
