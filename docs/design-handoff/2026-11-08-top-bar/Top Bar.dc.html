The Case top bar

Today’s bar, what is wrong with it, and two ways to fix it. Option B is the recommendation: the top bar says where you are and how the app is doing; the Case action bar, which already exists and is nearly empty, takes what you can do to the Case. Option A is the smaller change if the action bar must stay as it is. Option C is on the page for comparison only. Revised 2026-11-08 after two independent reviews and two of Matt’s calls: the status group is readable without colour, ranks its signals, is app-wide not per Case, and never paints a background; recording is a dot and a timer, not a REC pill; Settings comes up to 28px; the action bar names the section. The wash. The amber is warning-surface, a 10% tint of rgb(245,158,11) over the dark surface, and it lands as mustard. In the chrome no status paints a background any more: the border stays neutral and only the shield, its dot and its word take warning-fg. The three states shown: VPN not seen; a running session with failures; all nominal.

The recording pill. Red wash, pulsing dot, the word REC: a camcorder. Replaced by a plain 6px danger dot, a mono elapsed timer and the source in secondary text, with no pill, fill or pulse. The timer is the number an investigator checks when they glance back from the browser, and a steady dot is enough to say live. The second form, with the chevron, is the popover trigger on the dashboard and in Settings.

What changes. The three status pills become one control: three dots, one per signal (extension, Egress, Capture Health), faint while all is nominal. Off nominal, the worst signal’s icon joins its dot and both take that signal’s colour, with one short word; the pill itself is never filled. Ranking: Egress unknown (captures silently stop) first, capture failures second, “VPN not seen” last, since it is advisory. A disconnected extension never colours anything: it is normal for anyone using Launch browser. While a session runs the stored count stays visible, and a failure count always shows. Click opens the popover. Export becomes a plain icon button. The theme toggle leaves the bar; Settings → Appearance already holds it.

Why. Status should be glanceable: one thing to look at, coloured only when something needs you, and still readable without colour. Today a healthy app shows a green pill, an amber pill and a red pill at once, and the red one is a count, not a verdict.

Width rule. The Case name keeps at least 160px before the search shrinks; the search drops Ctrl F below 1,100 and becomes an icon below 900. The status word shows from 1,100 up (a widening: today the Egress words appear only from 1,536); below that the icon and dot carry it. Nothing else in the cluster changes.

What it costs. The action bar below stays as it is. Seven items drop to four plus the OS buttons, but the bar still mixes actions (Share, Export) with status and navigation, and the recording mark has to sit up here as well.

What changes. The top bar keeps identity and navigation: logo, breadcrumb with your Member Code chip and the full Case name, search, the status group from Option A, Settings, the OS buttons. Everything that acts on the Case moves to the 40px action bar it already has: Share, Export, Launch browser, and, while a session runs, the recording mark and the Capture Session switch. The action bar’s left side names the section (Notes), which today appears nowhere in the chrome: the rail is icon-only and the screen header is often scrolled away or behind a list pane.

Why. A reader scans a row for one kind of thing. Today’s bar asks them to find a status among actions and an action among statuses. Two rows with one job each read faster than one row with three, and the second row already exists; the code even says the session switch lives there so the top bar does not grow during recording. Share stays a visible word on every Case screen, which the sharing work settled; it moves one row, it does not hide. The section name is what makes the second row a row and not a second right-aligned cluster under the first.

What it costs. Share and Export sit 40px lower than muscle memory expects for a release, and the coachmark target moves with them. The dashboard and Settings have no action bar, so there the recording mark and the Capture Session controls stay in the top bar, as the Launched Browser page draws them (2c, 2d): recording lives in two places by route, and that seam is stated, not hidden. Settings gains the status group, which it does not show today. About 1.7 times Option A to build: the three status components merge either way; B also moves Share, Export and the recording mark into the action bar and gives it a route-aware left side.

RRules the recommended option follows
Shape says kind
Pills (rounded-full, all 28px) are status and the Share state only. Actions are 28px, 4px-radius buttons or icon buttons. No split buttons in the chrome; Export’s format choice is a menu on click.
No fills in the chrome
Status never paints a background. The -surface tints stay for inline lines inside dialogs and cards; in the bar, only an icon, a dot and a word take a -fg colour, and only for the worst signal. The Share pill keeps its own Egress glyph when the Egress is not Direct, so that state can appear twice; the rule is one coloured status control, not one coloured pixel.
Recording, without the camcorder
A 6px danger dot, a mono elapsed timer, the source in secondary text. No pill, no fill, no pulse, no “REC”. The timer says recording is live better than a blinking light does, and it is the one number an investigator checks mid-session.
Not colour alone
Off nominal, the worst signal’s icon joins the dots (the Egress indicator’s per-state icons already exist), so the state reads in grey. The group is one button with a full sr-only summary (“Status: 1 warning. Egress: Direct, VPN not seen. Extension connected. 23 Captures this session, 3 failed.”), aria-haspopup, and a polite live region that announces severity changes only, never each count.
What gives way, in order
Search keyboard hint (1,100) → status word (1,100) → action-bar labels (1,000) → search to icon (900) → Case name truncates last, never below 140px.
Tokens and sizes
Status: success / warning / danger -fg only in the chrome. Today’s raw emerald/red/slate values in the connection, recording and health components become these tokens in the same change. Settings comes up from 24 to 28px with the other icon buttons; this amends the brief’s fixed line, which kept 24 for a matched pair that no longer exists once the theme toggle leaves. Type 12/600 for the Case name and section, 11/500 for pills, 11 mono for the timer, 10 for the keyboard hint.
Screens without an action bar
Dashboard and Settings gain the status group (an addition) and keep the recording mark and the Capture Session controls in the top bar, as the Launched Browser page draws them (2c, 2d). The recording mark is the popover’s trigger there, with a chevron.
What the status group is not
Not per Case: the Egress is a setting, the extension connection is an app flag, the counts are this app session’s. Its popover’s Capture log button opens today’s Capture Health log (with Test pipeline and Test HTTP); nothing new is built behind it.
